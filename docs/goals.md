# 目标执行

在聊天输入 `/goal 需要完成的目标`，或在 `/` 命令菜单选择 Goal 后输入目标。
目标最长 4000 字符。该入口直接开始首轮工作，没有持久的输入模式开关；
后续普通消息仍是补充要求，不会替换目标。

聊天上方显示目标、状态与轮次。展开后查看累计 Token、运行时间、最近检查结果、
未完成原因及下一步；可暂停、恢复或清除。普通停止按钮也会暂停目标及其活动子任务。
`/goal pause`、`/goal resume`、`/goal clear` 提供相同操作。
执行中的目标必须先停止并等待子任务结束，才能替换。

## 执行链

用户创建目标 → 普通 Agent 执行工具 → 优先处理补充输入与子任务结果 →
没有待处理输入且子任务全部结束时检查完成情况 → 未完成则将下一步交回 Agent。
检查通过后进入完成状态。检查使用本轮绑定的模型和思考档位，不提供工具；
只接受结构正确的 JSON 判断，不把正文中的“完成了”直接作为完成状态。
检查器无法独立观察文件系统，依据是执行历史中的证据，因此它仍是模型判断，
不代替人工验收或项目本身的测试。

主 Agent 可以调用 `goal_read` 查询当前目标、预算和进度，不能通过工具创建、
替换或宣告目标完成。目标由 Go 业务核心拥有，桌面仅维护展示与草稿；
无桌面服务复用同一实现，断开客户端不停止已接受的执行。

状态为 `active`、`verifying`、`paused`、`budget_limited`、`complete`。
目标 ID 用于隔离迟到的检查结果和旧子任务；清除后不会被旧任务重新创建或唤醒。
fork 和侧聊得到普通会话，不复制目标的执行所有权。

## 用量与停止

可选预算通过 `goal.set` 的 `GoalInput.TokenBudget` 指定正整数；当前桌面命令入口
创建无预算目标，没有新增预算编辑表单。累计用量包含工作请求、Agent 流中断重试、
自动压缩、子 Agent 和完成检查，输入量已经包含缓存时不重复叠加。
Anthropic 的输入量加上缓存读取与创建量，缓存量仍作为其中的子集。

只有供应商实际返回完整输入/输出计数时，用量才算已知；显式零有效，缺失或部分
计数不伪装成零。详情展示已知下限与不完整提示。有预算时，缺失计数会停止后续
模型请求；无预算时保留不完整提示并允许执行。

预算是模型请求边界上的停止条件，无法精确预测一次调用的费用；已经发出的并发子任务
及单次回复可能使总量超过预算。达到预算后不再发新请求，不能用恢复按钮绕过；
需要用户设置新目标。尚未进入实际请求的排队输入保留，压缩也保留其输入身份。
目标完成后新到达的用户消息交给普通执行。

无效检查结果、检查请求错误或运行失败会暂停并显示原因，不标记完成。
用户暂停/清除会取消该目标的活动主任务与子任务。重启后未结束目标保持暂停，
不会自动重放工具或请求；运行时间只结算到最近持久化的心跳，心跳间隔 15 秒。

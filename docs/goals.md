# 目标执行

通过命令菜单插入的 Goal 引用可以放在正文开头、中间或末尾，系统以移除该引用后的正文作为目标。普通文本中的 `/goal` 仍仅在消息开头作为命令识别；目标命令携带附件时会明确报错，不会转为普通消息。

在聊天输入 `/goal 需要完成的目标`，或在 `/` 命令菜单选择 Goal 后输入目标。
目标最长 4000 字符。该入口直接开始首轮工作，没有持久的输入模式开关；
目标执行期间发送的普通消息可以补充要求。暂停和待恢复期间发送的消息按独立任务处理。

目标栏附着在输入框上方，待办面板位于目标栏上方。紧凑栏显示目标状态、目标内容与
按共享规则换算并保留到整秒的计时；轮次放在目标内容提示中。
图标按钮支持暂停、恢复、清除和打开右侧编辑页。
普通任务执行中或等待你回答时也可以点「恢复目标」或发送 `/goal resume`。目标栏随即显示
「目标待恢复」。宿主先让当前任务、它的后台子任务结果和已排队的输入处理完，再接回目标自己的待办。
等待期间点击「取消自动恢复」或发送 `/goal pause`，当前普通任务会继续。空闲时点击恢复会立即开始。
编辑页保留累计 Token、预算、最近检查结果、未完成原因及下一步。
目标执行期间，输入框的停止按钮会暂停目标并停止它的活动子任务。目标待恢复期间，此按钮结束当前普通任务，恢复预约仍然有效。
`/goal pause`、`/goal resume`、`/goal clear` 提供相同操作。单独 `/goal` 查看现有目标，
不会启动模型请求。未完成目标必须通过 `/goal replace <内容>` 显式替换；
执行中的目标必须先停止并等待子任务结束。
编辑目标内容使用独立的 `goal.edit` 命令，不替换目标 ID，不重置预算与计量；
按原目标 ID 和修订号校验冲突，草稿不会被其他编辑或会话切换覆盖。
下一次模型调用使用新内容，修改前已发出的完成检查不能宣告新目标完成。
面板来源、布局和测试见 [待办与目标附着面板](todos.md)。

## 执行链

执行模型结束一轮后，核心先处理补充输入和子任务结果，再读取成功的 TodoWrite 和
核心保存的待办检查点。还有工作时直接把进行中的待办交回执行模型，其次取第一项待处理工作。
记录了阻塞、取消或范围变化原因时，目标暂停并保留下一步。每次直接续跑推进目标轮次，
只有实际收到的模型验收判定才写入验收历史。

待办清空或全部完成后才发起模型验收。检查沿用本轮模型和思考档位，单独发起一次有界的
证据请求，包含目标、用户要求、当前待办、压缩摘要、最近的执行报告以及最多 12 条配对的
工具调用与结果。长输出保留首尾和省略标记，图像最多两张，编码数据合计上限 128 KiB。
验收器根据这些证据判断，证据不足时应给出具体的补证步骤。请求轨迹的来源为 `goal_verification`。

三种协议均指定唯一的 `submit_goal_verdict` 工具。供应商若明确拒绝强制工具选择，
核心保留同一工具和思考档位，在本次检查的尝试次数内改用自动选择，本轮后续验收沿用该选择。只有一次名称和参数
均有效的协议工具调用才能提交判定。验收通过后，目标进入完成状态。

主 Agent 可以调用 `goal_read` 查询当前目标、预算和进度，不能通过工具创建、
替换或宣告目标完成。目标由 Go 业务核心拥有，桌面仅维护展示与草稿；
无桌面服务复用同一实现，断开客户端不停止已接受的执行。

状态为 `active`、`verifying`、`paused`、`resume_pending`、`budget_limited`、`complete`。
待恢复期间保留原暂停原因、下一步和用量，真正接回目标时才开始累计目标时间和用量。
归档会撤销待恢复请求。客户端断开期间仍由宿主处理接续，宿主重启沿用中断后暂停的规则。
目标 ID 用于隔离迟到的检查结果和旧子任务；恢复执行会生成新 ID，保留计量与预算。
内容修订号隔离同一执行中的旧检查与编辑草稿。清除后不会被旧任务重新创建或唤醒。
分支和侧聊得到普通会话，不复制目标的执行所有权。

## 用量与停止

可选预算通过 `goal.set` 的 `GoalInput.TokenBudget` 指定正整数；当前桌面命令入口
创建无预算目标，没有新增预算编辑表单。累计用量包含工作请求、Agent 流中断重试、
自动压缩、子 Agent 和完成检查，输入量已经包含缓存时不重复叠加。
Anthropic 的输入量加上缓存读取与创建量，缓存量仍作为其中的子集。

只有供应商实际返回完整输入/输出计数时，用量才算已知；显式零有效，缺失或部分
计数不伪装成零。详情展示已知下限与不完整提示。有预算时，缺失计数会停止后续
模型请求；无预算时保留不完整提示并允许执行。

预算是模型请求边界上的停止条件，无法精确预测一次调用的费用；已经发出的并发子任务
及单次回复可能使总量超过预算。达到预算后不再发新请求，不能用恢复按钮绕过；
需要用户设置新目标。尚未进入实际请求的排队输入保留，压缩也保留其输入身份。
目标完成后新到达的用户消息交给普通执行。

同一待办连续交回执行模型八次后，如果期间始终没有工具结果或新用户输入，目标暂停并显示
原因和待办内容。恢复时重新读取当前清单，即使已保存的下一步为空，也能接回进行中的工作。

每次模型验收最多尝试三次，底层传输重试单独计数。验收仍失败时，如果上次有效判定留有
待执行步骤，核心将其交回执行一次。再次失败或缺少可执行步骤时，目标暂停并显示原因。
成功收到有效判定后重置这次恢复机会。运行失败会暂停并显示原因。
用户暂停/清除会取消该目标的活动主任务与子任务。重启后未结束目标保持暂停，
不会自动重放工具或请求；运行时间只结算到最近持久化的心跳，心跳间隔 15 秒。

## 目标操作诊断日志

桌面目标管理入口在运行日志中分别记录 `goal action started`、
`goal action execute finished`、`goal action snapshot finished`。
记录命令类型、会话 ID、目标 ID、请求 ID（调用方未提供时为空），以及两个阶段各自的
耗时和错误。执行成功但刷新失败时，执行记录为 `error=<nil>`，刷新记录保留实际错误；
两个阶段同时失败时分别保留，界面继续显示原始执行错误。日志不记录目标正文。
默认数据目录下文件为 `~/.gcode/logs/gcode.log`，自定义数据目录以实际运行配置为准。

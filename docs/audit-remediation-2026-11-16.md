## 原报告纠正

- Anthropic 连续同角色消息由官方服务合并，不能推出“并行工具调用必然 400”。
  主动合并是请求规范化，第三方网关的限制需要具体响应证据。
- 旧 provider-key GET 的查询参数为供应商 ID，不是 API key。当前显式 reveal 接口仍按
  用户操作向已认证客户端返回完整 key；真实收益是明确动作、禁止缓存和审计，
  不是移除远程持有者的凭据读取权。
- Goal 在会话正文中持久化，加载时恢复；索引清空字段与回收投影不等于丢失目标。
  已有 `TestGoalRestartPausesAndSettlesToLastHeartbeat` 覆盖重启暂停与保留预算。
- MCP 请求等待超时与 stdio 写管道超时不能混为一谈。前者可取消单次请求；
  后者可能已经写出不完整协议帧，关闭连接是必要的失败隔离，不能直接删掉。
- 特定 tokenizer 对中文的精确比例、CI 的耗时外推和未经执行的原生测试不列为实测结论。

## 权限与性能边界

工具以宿主 OS 用户权限运行，Hook 权限模式为 bypassPermissions。
后续已确认采用[受信宿主执行](execution-trust.md)，不将系统沙箱或通用危险命令
分类器作为当前待修能力。环境白名单和 Write/Edit 目录边界有各自职责，
不限制 Bash 的全部文件访问；同 OS 用户运行的插件和 MCP 属于受信代码。

首次验收只补足静默刷新和投影复用，尚未移出锁内保存。
后续改造将编码和持久化 I/O 移出状态锁，并以独立事务门保持提交顺序和回滚边界，
详见[会话存储](session-storage.md)。修改命令仍串行，不能声称所有命令都不等待磁盘。

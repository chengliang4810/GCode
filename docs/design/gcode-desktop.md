## 2. 发送方式：纠正与队列

### 已确认语义

设置页提供“默认发送方式”，选项为“纠正”和“队列”，出厂默认“纠正”。运行中仍可为单条消息显式选择另一种方式。

| 方式 | 行为 |
|---|---|
| 纠正 | 停止当前任务并发送新指令。完成当前任务的取消与必要资源清理后，使用保留的会话上下文启动新任务。 |
| 队列 | 当前任务继续，新消息等待其结束后执行。待执行消息可以查看和撤回。 |
| 空闲时发送 | 直接开始新任务，两种运行中发送方式在此时没有打断或排队的区别。 |

纠正沿用“停止并发送”的语义。已发出的请求和已经发生的工具副作用无法被追溯修改；纠正不自动撤销文件。

### 已确认的边界规则

1. 默认发送方式是全局用户偏好，重启后保留；只影响之后的发送操作，不重排已有队列，不改变已经执行的操作。
2. 纠正消息优先于已有队列执行，原有队列保留并可撤回；用户可检查旧排队任务是否仍适用。
3. 同一会话取消尚未完成时不启动新的 Agent 任务。界面显示取消状态，保留待发送内容；取消失败时展示错误，不伪装成已经开始新任务。
4. 纠正取消旧任务的授权/提问等待。旧请求失效，不把新消息当作授权回复，迟到的旧回调不能影响新任务。
5. 显式“停止”、执行失败或应用重启后，队列保留并暂停，由用户主动继续。当前任务正常完成时，按队列顺序继续。
6. 所有已提交消息均有持久化标识和明确状态；连续纠正或取消期间的输入不得静默丢失，也不得导致同一会话出现两个并行执行循环。

这些规则限制的是同一会话内部的顺序，不限制不同会话并行。

## 6. 工程结构

首版采用一个 Go 桌面应用，通过直接 Go 调用连接 UI 和运行内核；后台工作在 goroutine 中执行。按职责划分，优先复用现有包，不建设通用消息总线或跨进程 RPC 平台。

UI 与 Agent 内核之间不使用 ACP。依据是二者处于同一个 Go 进程，而非“原生 UI 自动取消通信需求”。发送、停止、纠正、队列和授权回复通过类型明确的 Go 方法交给会话控制；流式文本、工具结果、授权请求和状态通过进程内回调/事件返回。仍需维护事件顺序、session/run 归属、取消和有界输出；无需为内部交互增加 JSON-RPC 编解码或 stdio/WebSocket 桥接。

模型服务 API、MCP 以及命令/终端的进程通信各自保留所需协议。若以后出现独立 Agent 服务、远程执行或外部 ACP 客户端接入的实际需求，再评估相应适配层；当前内核保持独立于 UI 的 Go 接口，不预建该通信层。

| 边界 | 责任 |
|---|---|
| 桌面入口/视图 | mygo 生命周期、窗口、三栏、输入、授权与提问界面、主题、系统托盘/菜单。 |
| 会话控制 | 每个会话的执行状态、纠正/队列、运行 context、授权等待、模型配置快照和结构化事件。 |
| Agent 内核 | Agent loop、provider、工具、sandbox、扩展能力；不依赖 mygo 或桌面控件。 |
| 执行资源 | 明确归属的命令、终端、MCP 连接与子代理；不能通过全局默认 manager 跨会话控制。 |
| 会话存储 | 有序追加事件、元数据、历史重放、上下文恢复、已提交待执行消息。 |
| 工作区服务 | 目录、文件、Git 状态/Diff、worktree、外部编辑器。 |

UI 只消费与当前 session/run 关联的事件。后台 goroutine 通过 mygo 的 `Window.Update` 主线程调度入口更新展示；网络、Git、文件扫描、Markdown/高亮处理不能阻塞 UI 主线程。

会话展示历史和下一次模型请求上下文分别由同一份会话事实构造，保留正确的 tool call/result 对应关系。中断时保留已确认的输出与工具结果，标记未完成操作；不能恢复成只有用户/助手文本的简化历史。

凭据留在本机专用凭据存储，配置引用凭据；日志和会话事件不记录密钥。具体存储实现先评估现有 credstore 的平台能力。

## 7. 并发与资源归属

1. 会话之间独立运行，不设置项目级任务队列，不通过持有整个工作区的长期锁把 shell 命令串行化。
2. 每个会话有独立的运行 context、进程管理归属、待授权请求和输入队列；停止及 write_stdin 等控制必须校验归属。
3. 内置文件编辑在最终内容校验和落盘的短阶段按目标路径协调，同路径操作重新验证前置内容。不同文件可同时修改；不在模型推理、用户授权等待或整个任务期间持有文件锁。
4. 文件协调只能覆盖 GCode 管理的操作。任意 shell、外部编辑器及其他进程不受该协调保证；检测到变化时返回冲突并要求重新读取。
5. 项目 Diff 是共享工作目录当前状态。直接文件工具可记录明确的 before/after；命令运行期间观察到的目录变化可能混入其他来源，不能全部标记为该会话独占改动。
6. 不自动执行整目录 rewind/reset。不将来源不确定的修改作为安全的一键撤销对象。
7. 不限制会话数不等于承诺无限机器资源：输出缓冲和展示事件需要有界或合并；资源不足、服务限流等明确报错，不能静默取消其他会话。

- 子代理启动必须改为桌面运行时提供的执行路径，不能继续依赖已删除的 zero 用户 CLI。

## 8. Worktree 行为

新建会话默认使用所选本地目录。开启 worktree 时：

- 默认从当前分支 HEAD 创建，也允许选择其他本地分支；记录实际使用的完整提交。
- 创建独立分支和工作目录，明确显示来源、分支及实际 cwd。
- 不复制源目录的未提交、未跟踪或忽略文件；界面明确提示。创建过程中不 stash、reset 或修改源工作目录。
- 会话结束、关闭窗口、退出应用或重启均不自动删除 worktree。
- 合并或删除由用户触发。删除前检查正在使用它的会话和待保留工作，不连带操作用户的其他 checkout。

旧的 detached worktree 与 `Prepare` 自动清理路径已从 GCode 移除。当前 `internal/worktrees.Manager` 只创建独立分支 worktree，并由 session 绑定、脏状态检查和显式删除/合并操作负责归属；任务完成、关闭窗口、退出应用或重启都不会触发自动清理。

## 9. 分阶段交付

| 阶段 | 交付与完成条件 |

| 1. 源码接管与原生样板 | 核实并记录来源，迁出运行时组装，建立 GCode Go module/数据目录/桌面入口；保留核心测试并完成裁剪依赖检查。首个原生窗口落实主题与代表性工作台样板，确认视觉方向。 |
| 2. 一条真实编码链路 | 原生窗口中配置一个 API 服务，打开项目，发送任务，流式显示、授权、读写文件、执行命令、停止、保存历史并重启继续。 |
| 3. 会话并发与输入控制 | 同目录多个会话真实并行；进程和授权隔离；纠正、队列和默认偏好；取消、失败、恢复边界通过验证。 |

## 10. 验收条件

### 运行与恢复

- 真实 API 完成读文件、修改文件、运行验证和报告结果；四类 API 分别验证工具调用、错误、取消和历史上下文。
- 停止一个会话不终止另一个会话或用户独立打开的终端。
- 中断/重启后历史、工具结果、状态和已提交待执行消息可恢复，不自动重跑任务。
- API Key、运行输出和错误经过适当脱敏，项目文件中不出现应用密钥。

### 并发与纠正

- 同一目录至少三个主会话并行；这是验收负载，不是产品并发上限。
- 两个内置编辑同时基于旧内容写同一路径时，不能双方静默成功；不同路径仍可并行。
- 命令与外部编辑造成的共享变更正确展示，不虚构独占归属或自动回滚。
- 纠正发生在流式输出、长命令、授权等待、Agent 提问及已有队列时，消息不丢失，不重复执行，不泄漏旧授权。
- 默认方式切换并重启后保留；单次选择另一方式不擅自改全局偏好。

### 原生界面与终端

- 对照 motrix-mygo 的视觉规范检查字体、间距、圆角、图标、颜色和状态一致性；保留 GCode 实际原生窗口的浅色/深色及窄窗口截图，使用真实中文内容，不以离屏渲染或编译通过代替视觉验收。
- 代表性样板的视觉方向确认后再扩展其他页面；新增页面沿用共享规范。检查输入区、发送方式、停止、权限操作和系统窗口按钮没有被遮挡或裁切。
- 中文输入法组合、候选位置、Enter/Escape、复制粘贴和焦点切换在真实原生窗口验证。
- 长会话、流式增高、历史加载、代码长行、大 Diff、CJK/emoji 和主题切换不破坏选区或阅读位置。
- PTY 创建、输入、连续 resize、滚动、复制、shell 退出和关闭后的资源释放真实运行验证。
- libghostty-vt 在实际应用包中可被正确加载，不能只验证开发目录。
- 分别报告 macOS Intel、Apple Silicon 和 Windows 的编译、原生运行与未验证项；交叉编译不能替代目标机器验收。
- 记录启动耗时、空闲/长会话/并发任务内存及交互延迟；当前没有约定硬性数值门槛，不以演示项目数据代替 GCode 实测。

### Worktree 与退出

- 来源提交准确，源目录未提交内容未被修改；新目录/独立分支与会话绑定正确。
- 任务完成及应用重启后 worktree 仍存在，超过旧清理时间也不被自动删除。
- 关闭窗口任务继续；显式退出只清理应用管理的运行资源，保留会话数据与工作目录。

## 11. 风险与尚未验证事项

- 并发内核、通用 Responses 和原生文档展示都是实际开发工作，不是替换入口即可完成。
- mygo 有中文输入、虚拟列表和终端源码能力，但 GCode 上的稳定性仍须实测。PTY 的 EAGAIN 路径是待验证线索，尚未在本轮复现，不先认定需要修复。
- motrix-mygo 证明同栈可以实现统一的视觉外观；其下载器页面不能证明长对话、代码选择、Diff 与终端的交互质量，这些须在 GCode 样板及真实任务中验证。
- 单进程方案简化集成，但不提供操作系统级的会话崩溃隔离；事件落盘、资源归属及取消边界必须完整。
- 非受控 shell 和外部编辑共享目录的风险已经接受，产品不得宣称具有 worktree 级隔离。
- 没有完成全树来源比对、真实模型调用、构建、性能测试或平台实机验收。本文是实现与验收依据，不是完成报告。

# 供应商导入与导出

供应商设置页可以以一个 JSON 对象在机器之间搬运供应商配置。

## 位置

- 顶部操作行：「导入供应商」位于「添加供应商」左侧，使用共享次级按钮
  （`buttonWithIcon` + `document` 图标）。
- 已添加供应商的 `Provider actions` 菜单：「导出供应商」紧跟「删除供应商」之后。

## 导入

模态弹窗内可直接粘贴 JSON，或用弹窗内的「选择文件」读取本地 `.json`，
两条路径共用同一份校验。文件上限 1 MiB。

文档就是单个供应商对象（`model.Provider` 的 JSON 字段：`name`、`protocol`、
`baseUrl`、`apiKey`、`models` 等）。空名称、非法协议、非法 Base URL、
重复模型 ID 或未知字段都会被拒绝，原因显示在弹窗内，不会写入核心。

导入总是分配新的供应商 ID 并忽略文档里的 `id`，因此同一个文件可以重复导入，
不会覆盖它来自的那份配置。API Key 交给核心加密保存；弹窗关闭后不保留粘贴内容。

## 导出

菜单项打开弹窗，后台通过 `ProviderKeyService.RevealProviderKey` 读取已保存的
Key，弹窗显示包含**明文** API Key 的 JSON，并在下方说明这一点。
「保存为文件」使用系统保存对话框，以 0600 权限写入 `.json`，
默认文件名是供应商名的小写 slug（非 ASCII 字符折叠为 `-`，为空时用 `provider`）。

导出的文件可以直接被导入回来：往返后连接参数不变，ID 是新的。

## 验证

`TestProviderImport*` 与 `TestProviderExport*` 覆盖：

- 导入按钮位于「添加供应商」左侧、导出口在「删除供应商」之后；
- 粘贴导入写入真实核心，并可通过 `RevealProviderKey` 取回密钥；
- 非法 JSON（缺名称、未知字段、非法协议、数组）被拒绝且不落库；
- 「选择文件」把文件内容填入文本域；
- 导出 JSON 含明文密钥，保存的文件与弹窗内容一致；
- 导出文件再次导入的往返；
- 浅色/深色主题与 520/1100 宽度下弹窗不越界；
- 导出文件名的 slug 规则。

这些都是 `ui.Tester` 与本机真实核心的证据，代表的不是已安装应用或真实供应商。

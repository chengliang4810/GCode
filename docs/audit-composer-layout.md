## Read-only IME snapshot patch

MyGo v0.7.3's public API exposed only a composing boolean before this patch, so
measuring the bound draft could not account for long preedit. Revision `rcode-native-ui.20` adds the
small read-only `InputDisplayText()` API, generated by the existing checked API
generator. It returns native display text including preedit; passwords remain
masked. It changes no editing or threading semantics.

The composer retains only plain strings for the measured display snapshot and
its corresponding committed draft. A following layout pass measures preedit
without writing it into the draft; an external draft update bypasses an older
snapshot. The input's live `Composing()` value is captured as a plain boolean
for Enter handling. This prevents IME confirmation from sending an existing
nonempty draft. No `ui.Element` or `ui.Context` is stored in app state or a worker.

The input-display-text patch is `patches/mygo-v0.7.3-07-input-display-text.patch`,
SHA-256 `0c6af413ebc7c707d303c40b211e129e0ac2fa0cddd53d268463642d5bd36159`.
The source lock, framework verifier, runtime revision marker, current README and
license notices were updated together. The license manifest was regenerated.
Current source tree: 2,034 files, SHA-256
`f86d8641763cfe81281450f382687d4c09fc6a528f50b4a861def7ce669ea72d`.

Two regressions were found by stronger tests before correction. With a nonempty
draft, the previous Enter handler called send during IME composition (`sends=1`)
even though composition and focus survived the layout change. The old empty-draft
IME test masked this because sending an empty draft was rejected. Also, deriving
wrapped line count by dividing natural glyph heights over-counted a CJK/emoji
sample (250.25px versus the native textarea's 227.5px). Native textarea auto-grow
now owns the latter calculation; the new tests pass after both corrections.

Final review added two more failing boundary regressions before fixes. A
12-line native allowance stopped long input early at interface fonts 12, 13 and
14 (textarea224.75/241.8125/258.875 instead of260); the allowance is now100 and
the pixel cap owns scrolling. Also, a keyed input replaced by ordinary or
selectable text retained an old editor in framework state; checking the current
editable flag now enforces the snapshot API's empty-result contract.

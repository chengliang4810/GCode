# 对话用量、速度与缓存命中率

主对话及侧聊输入框下方的右侧显示累计 token、平均输出速度和平均缓存命中率。
回复末尾沿用复制操作区的悬停显示规则，在复制按钮旁显示该次回复的
token、速度、缓存命中率和实际供应商名称 / 模型 ID；悬停统计文字可查看输入、输出、
缓存命中和各模型明细。

统计由实际模型请求记录驱动，不使用当前选中的模型推测历史身份。
一次回复中的工具循环、重试、模型 Hook、自动上下文压缩和目标验证均计入
对应运行。后台命名计入对话汇总，手动压缩计入它自己的运行。
父对话及对应回复包含其委派的子智能体与后代请求；侧聊独立计算，
分叉继承的文本不重复计费，分叉之后的新请求属于新对话。

总用量为每次请求的输入与输出之和。输入已包括缓存读取；
Anthropic 的缓存创建也已在协议层并入输入，不能再次累加。
失败、取消和重试中已上报的用量仍然计入。
不完整用量显示 `≥已知量`；完全没有已知量时显示 `—`，
真实上报的零用量显示 `0`。未记录请求的历史不估算、不迁移。

平均速度为有可用数据的请求的 **输出 token 总和 / 生成时间总和**，
不是各次速度的算术平均。生成时间使用单调时钟，从第一个实际输出片段
（文本、思考或工具参数）到流结束，不包含首字等待和工具执行。
没有观察到流式输出、没有输出计数或生成时间为零时不推算速度；
详情显示可参与速度计算的请求数，避免将部分数据误认为完整覆盖。
该指标是客户端观察到的流接收速度，网络缓冲也会影响测量。

平均缓存命中率为有明确缓存读取计数与输入计数的请求的
**缓存命中 token 总数 / 输入 token 总数**，不平均各次请求的百分比。
未返回、返回 `null` 或无可用输入计数的请求均不参与分子和分母；
明确返回缓存命中 `0` 的请求仍参与统计，不把未知当成零命中。
缓存计数大于输入计数或为负数时也不参与命中率。所有请求均无数据、
或参与请求的总输入为零时显示 `—`，详情显示可用缓存数据的请求数。
Chat 同时读取标准 `prompt_tokens_details.cached_tokens` 和当前协议扩展
`prompt_cache_hit_tokens`，以标准字段明确返回的值优先。
Anthropic 输入按未缓存、缓存读取和缓存创建之和计算，缓存创建不算命中。

请求记录保存在所属对话的内容寻址记录中，随快照和远程状态同步；
不写入全局配置索引、不保存凭据、不增加本机 UI 与核心之间的传输。
现有应用级用量页仍以持久化消息去重计数；它与此处按实际请求统计的
范围不同，重试、命名、压缩等费用会使对话统计高于旧用量页。

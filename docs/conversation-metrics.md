# 对话用量、用时与缓存命中率

主对话及侧聊输入框下方的右侧依次提供用时、用量两个悬停入口：
用量入口显示累计 token 与平均缓存命中率，
用时入口显示轮次、模型请求步骤数和累计生成耗时。
该区域默认隐藏，收到第一条可展示的用量、生成耗时或缓存命中率数据后才显示；
仅有请求记录、失败状态或全部未知的占位值不会触发显示。明确上报的零用量属于有效数据。
切换会话时按目标会话自己的统计决定显隐，已有有效数据不会因后续请求失败而隐藏。
运行失败详情保留在对话正文中，左下角不再重复显示“运行失败”状态。
回复末尾沿用操作区的悬停显示规则，依次排列“复制 → 用量 → 用时 → 日期”；
面板打开期间操作区保持可见。悬停用量打开完整面板，显示总量、输入、缓存读取、
输出和缓存命中率。回复面板额外显示实际供应商名称 / 模型 ID，
同轮使用多个模型时逐项列出各模型明细；对话汇总不按模型拆分。
中文数量按千、万、亿显示，字段悬停可查看精确 token 数。
悬停用时打开耗时面板；同组两个面板互斥，移动到另一入口时直接切换。
指针移入面板后保持显示，离开入口和面板后延迟 180ms 关闭，以便跨过两者的间隙。
点击外部或 Escape 也可关闭；Escape 关闭后，仍停在原入口不会立即重新打开。
保留键盘激活入口打开面板的操作，使用 Escape 关闭。
面板复用共享浮层和控件样式，窄窗限制宽高并允许滚动，
回复面板沿入口左边定位，空间不足时自动翻转。

统计由实际模型请求记录驱动，不使用当前选中的模型推测历史身份。
一次回复中的工具循环、重试、模型 Hook、自动上下文压缩和目标验证均计入
对应运行。后台命名计入对话汇总，手动压缩计入它自己的运行。
父对话及对应回复包含其委派的子智能体与后代请求；侧聊独立计算，
分叉继承的文本不重复计费，分叉之后的新请求属于新对话。

总用量为每次请求的输入与输出之和。输入已包括缓存读取；
Anthropic 的缓存创建也已在协议层并入输入，不能再次累加。
失败、取消和重试中已上报的用量仍然计入。
不完整用量显示 `≥已知量`；完全没有已知量时显示 `—`，
真实上报的零用量显示 `0`。未记录请求的历史不估算、不迁移。

用时为统计范围内实际测得的生成耗时之和，不依赖供应商是否返回输出计数。
生成时间使用单调时钟，从第一个实际输出片段
（文本、思考或工具参数）到流结束，不包含首字等待和工具执行。
多次请求、委派请求的时间累加，存在并行时不等于整轮墙钟耗时；
没有观测到生成时间时显示 `—`。
详情中的平均速度为有可用数据的请求的 **输出 token 总和 / 生成时间总和**，
不是各次速度的算术平均。
没有观察到流式输出、没有输出计数或生成时间为零时不推算速度；
该指标是客户端观察到的流接收速度，网络缓冲也会影响测量。

用时详情还显示模型请求总耗时、工具执行累计耗时、平均首字等待、生成耗时和输出速度。
用量与用时面板均不显示计数覆盖行，用时面板不显示速度口径说明文字。
模型请求耗时按每次实际请求分别记录并累加，从该次尝试开始至结束，
不包含两次尝试之间的退避等待；首字等待截至该次尝试的第一个文本、思考或工具参数片段。
首字等待按有观测记录的请求取算术平均，未观察到输出的请求不参与。
这些新增计时随请求记录持久化；没有记录的历史显示 `—`，不反推。
工具耗时为当前统计范围内已结束工具的执行时长之和，
并行工具与子智能体可能重叠，因此不是整轮墙钟耗时。
轮次为主会话有请求记录的不同运行数，后台命名不额外增加轮次；
步骤为统计范围内的请求记录数，包含重试、维护与委派请求。

平均缓存命中率为有明确缓存读取计数与输入计数的请求的
**缓存命中 token 总数 / 输入 token 总数**，不平均各次请求的百分比。
未返回、返回 `null` 或无可用输入计数的请求均不参与分子和分母；
明确返回缓存命中 `0` 的请求仍参与统计，不把未知当成零命中。
缓存计数大于输入计数或为负数时也不参与命中率。所有请求均无数据、
或参与请求的总输入为零时显示 `—`。
例如总输入 9.2 万、缓存读取 2 万、覆盖 5/7 时，
命中率使用这 5 次请求的输入作分母，不能直接用 2 万除以 9.2 万。
Chat 同时读取标准 `prompt_tokens_details.cached_tokens` 和当前协议扩展
`prompt_cache_hit_tokens`，以标准字段明确返回的值优先。
Anthropic 输入按未缓存、缓存读取和缓存创建之和计算，缓存创建不算命中。

口径参考本机 `D:/projects/deepseek-harness` 的
`packages/client/ui-chat/src/client/contract/turn-metrics.ts` 和
`packages/client/ui-chat/src/client/chat/StatsPills.tsx`，只读取参考项目。

请求记录保存在所属对话的内容寻址记录中，随快照和远程状态同步；
不写入全局配置索引、不保存凭据、不增加本机 UI 与核心之间的传输。
现有应用级用量页仍以持久化消息去重计数；它与此处按实际请求统计的
范围不同，重试、命名、压缩等费用会使对话统计高于旧用量页。

验证包括三协议用量与流计时、真实本机核心的重试/工具循环/跨供应商调用、
持久化重开、快照隔离、远程 JSON 往返、子智能体范围与缺失/零值、
复制内容保护、共享组件门禁以及 Windows 原生深浅主题/窄窗。
原生模型端使用本机 HTTP 流夹具，不代表真实供应商或远程实机验收。

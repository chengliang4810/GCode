# 聊天链接解析性能优化

运行采样发现聊天 Markdown 的链接解析开销。每次 `LinkSourceAvailable` 或
`LinkRoot` 都会建立包含全部会话的映射；一个链接会多次进入该检查，
反复分配与当前会话无关的数据。

现在先查找来源会话，再沿父级验证它属于当前工作区。根会话命中后立即返回；
遍历步数最多为会话数量，循环关系或缺失父级仍会拒绝访问。
不增加缓存，不改变来源绑定、工作目录解析、归档判断、远程动作限制及点击路由。
因此目录或父级关系更新后直接读取最新快照，没有持久缓存失效窗口。
深层祖先查找采用线性扫描，此次收益主要针对常见的根会话及浅层侧聊。

回归覆盖根/子/孙会话、无关会话、缺失父级、循环关系、归档、目录更新、
重新挂接父级及关闭工作区；保留原有中文文件、Markdown、复制、菜单和远程动作测试。

## 性能证据

同一 checkout、Go 1.27.3、macOS amd64、Intel i7-9750H，
前后各运行 6 次，每次 `-benchtime=200ms`，使用 benchstat 比较：

| 基准 | 耗时变化 | 每次分配字节变化 |
| --- | --- | --- |
| 根会话解析，100 个会话 | 91.02 µs → 0.354 µs，-99.61% | 45,096 B → 0 B |
| 四个文件链接，100 个文件 | 142.47 µs → 68.84 µs，-51.68% | 约 5.26 KiB → 1.95 KiB |
| 四个文件链接，5,000 个文件 | 182.69 µs → 82.73 µs，-54.72% | 约 5.20 KiB → 1.92 KiB |

根会话解析 p=0.002，两个文件链接耗时比较 p=0.026，分配字节比较均为 p=0.002。
根会话基准的目标位于快照首项；其他位置仍需要线性查找，不能套用该耗时。
文件链接基准复用已有 `BenchmarkTranscriptFileLinks`；它包含完整解析流程，
因此比只测根会话更接近实际调用。原始记录在
`output/runtime-optimization-20261112/`。同机其他任务导致耗时波动较大，
这些结果不等于整个聊天界面或应用的 CPU 降幅。

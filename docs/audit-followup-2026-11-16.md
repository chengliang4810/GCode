# nq7723skhoru 后续逐项核实

本页基于 2026-11-16 当前源码与隔离测试。原审计会话包含多轮相互修正的结论，
不能把第一轮报告的每条描述都当作当前缺陷。执行信任边界已明确为

## 本轮持久化改造

状态锁只保护状态准备、内存读取和保存结果安装。独立事务门从修改开始持有到
保存或失败回滚结束；JSON 编码、摘要、正文/索引写入和旧记录清理在状态锁外执行。
周期刷新、执行消息和模型用量属于实时进度保存，允许已加载会话与元数据快照在
磁盘提交期间继续读取。命令和最终收尾保留读取屏障，避免提前暴露成功状态，
同时避免并发修改被整体回滚覆盖。没有引入异步成功回执或并行写事务。

实时进度快照不保证其内容已经落盘。事务快照等待修改者完整提交或回滚；
首次加载未驻留会话、建立订阅和修改命令也需要事务门，不能据此声称
“所有命令在慢盘下都不会等待”。后续若要求并行写事务，需要另行设计冲突及回滚边界。

针对 `Open`、测试及 benchmark 中原有的未持锁保存调用，统一补上显式锁。
事务入口 `persistLocked` 与进度入口 `persistProgressLocked` 共用同一编码/提交实现，
明确区分读取屏障；它们都同步等待保存，不是旧版本兼容路径。

验证中曾发现完全放开实时快照会提前观察到运行结束、但目标输入尚未完成收尾；
最终实现保留上述事务读取屏障，并增加失败回滚读取测试及目标 Hook 多次回归。

## 已复现、仍待处理

| 项目 | 核实结果 | 证据与建议 |

| 附件解码与批次内存 | 确认有资源成本问题，但不是“无限制上传”。单文件 24 MiB、批次 96 MiB、数量 20；HTTP JSON 入口却允许 140 MiB，核心在完整解码后校验，原生及客户端路径批次也在读取所有文件后才检查总量。 | `internal/remote/resources.go`、`internal/engine/attachments.go`。隔离 handler benchmark：24 MiB 数据一次解码累计分配 159,407,440 字节，约 152 MiB；这是累计分配量，不是峰值 RSS，且不含核心复制。建议降低单次传输边界，并在每个文件读取前检查剩余额度；需要更低峰值时改流式二进制上传。 |

| 保存事务内重复根验证 | 静态确认：`writeSessionRecord`、`cleanSessionRecords`、独立终端路径分别调用 `storage.Resolve`。 | 当前都已随持久化 I/O 移出状态锁，但调用次数未减少。若后续实测需要，可在单次提交内复用已打开的根，不使用跨提交 TTL 放宽目录身份校验。 |

## 按当前契约成立，不作为漏洞修复

| 原报告项目 | 当前判断 |
| --- | --- |
| Bash、插件、MCP 使用宿主权限 | 用户明确选择受信宿主执行，属于产品契约；环境白名单是默认传参策略。 |
| 插件 `${VAR}`、敏感选项环境传递及启用后运行 | 是受信组件的显式配置与执行通道，不增加首次启动确认或另设 OS 沙箱。 |
| MCP / 图标服务可请求回环和私网 | 请求由用户配置或认证客户端触发，本机和内网服务属于正常用途，不能仅凭能访问私网认定越权 SSRF。图标抓取已有同源引用/重定向限制及响应上限，回环 HTTP 实测覆盖它们。未请求真实云元数据。 |
| 远程目录选择可列宿主任意目录 | bearer token 是宿主控制权限，目录选择属于授权能力；不等于匿名目录遍历。 |
| API 错误包含内部路径 | 认证后的宿主控制客户端本就能访问对应宿主信息；诊断文本仍需避免携带凭据，不能将所有原始错误一概视为越权。 |
| 流中断后的显示文本与模型 history 不同 | 显示可以保留未完成结果，模型历史只接收完整执行消息，避免重放不完整调用。重试会替换未完成显示块。仅凭两个列表长度不同不能认定数据损坏。 |
| Responses 最终文本与增量不匹配时报错 | 当前是失败封闭策略，避免拼接出错误答案。错误分类仍可改善；未经明确的修订事件契约，不应静默替换已展示内容或补造增量。 |
| 无效工具调用可重试 | 允许模型修正参数，且有重试上限。不是无限执行，也不会把不完整工具批次送去执行。 |
| JSON 中供应商及插件敏感配置明文保存 | 当前是宿主私有配置文件策略；不能把“明文”本身当作跨权限泄漏的实证。系统密钥库属于独立产品能力。 |
| macOS / Linux 浏览器 profile 不受自定义数据根管理 | MyGo `SetWebViewDataDirectory` 明确仅支持 Windows。非 Windows 返回 `ErrUnsupported`；这是平台能力缺口，本轮未实测平台默认 profile 的位置或权限，原报告的固定 `0755` 结论不采信。 |

## 已有约束或原判断过强

| 项目 | 复核结果 |
| --- | --- |
| 媒体缓存无上限 | 原判断错误：`internal/desktop/media.go` 明确有 16 项 LRU；仍是按条数而非解码字节计量。 |
| 文件图标缓存随文件名无限增长 | 原判断错误：键来自内置 `file-icons.json` 的图标路径加深浅主题，文件名只参与查表，不直接成为缓存键；没有显式 LRU 不等于无界。 |
| artifact 全局缓存跨 App | 静态确认它缓存内置资源的 SVG。共享不可变内置资源本身不能证明泄漏；没有发现按会话正文累积条目的路径。 |
| 公式缓存跨 goroutine 保存 UI 元素 | 缓存按 App 创建，有 256 项 / 8 MiB 淘汰和长度 32 的队列，worker 随 context 取消。完成后清空等待服务；`SVG` 和 `Services.Invalidate` 不等同于持久保存 `ui.Element` / `ui.Context`。仍不据此宣称所有原生资源生命周期均已验收。 |
| 目标会在重启后丢失 | 已由正文保存/恢复和重启暂停测试纠正；索引省略 Goal 是分层存储，回收投影不等于删除正文。 |
| MCP 单次超时永久破坏全部工具 | 普通等待取消与 stdio 帧写入失败是不同路径。写出半帧后关闭连接属于协议失败隔离，不能统一删除。 |
| MCP Capabilities 没加锁 | 当前写入只发生在连接构造/握手期间，成功返回后只读，并通过 JSON 复制后返回调用者。未找到运行中更新路径，不能仅因没有锁判为数据竞争。 |
| checkout 请求取消 | 准备使用请求 context，尚未被持久运行接受时可取消，并有 `cleanupUnacceptedCheckout`；已接受运行的生命周期归宿主。二者不能混为客户端断开取消任务。 |
| 命令回滚浅拷贝 history/context | map 拷贝确实只复制容器；但必须找到事务中就地覆盖原消息的具体路径，才能证明回滚失败。本轮未构造出这种丢失更新，不能只凭 `maps.Clone` 判定缺陷。本轮事务门还保证保存期间没有第二个修改者进入。 |
| UI 共享控件 | 门禁已覆盖 settings 页及 desktop 中共享按钮调用，但仍不跨包检查 workbench 控件。覆盖缺口属实；视觉统一继续暂停，不在本轮重构控件架构。 |
| UI 本地化与稳定 key | `settings_usage_charts.go` 仍直接显示 `"Tokens"`；浏览器工具栏及命令页签部分按钮仍依赖 label 而无显式 key。属于静态确认的规范覆盖项，本轮未以多语言原生流程验收，也未修改视觉布局。 |
| CI race 必然超时 | 本机耗时不能推出云端必然失败。已存在核心 race 和原生入口；GitHub Actions 实际运行结果仍未验证。 |

# 会话存储与运行数据目录

本页记录 2026-10-30 已实现的存储规则；验收证据另见
[存储验收](storage-acceptance-2026-10-30.md)，以源码与实际测试结果为准。

- 配置入口默认为 `~/.gcode`；`--data-dir` 建立独立配置入口。设置、供应商、
  用户技能、命令、MCP/插件配置、连接凭据和少量会话/目录索引保留在入口。
- 运行数据目录可以切换，下次启动生效。切换只登记新根，不复制、移动或删除
  原目录；不得为了完成切换自动转换旧版本存储格式。
- 会话创建时绑定运行根。旧会话的消息、上下文、执行记录和产物始终回到原根，
  新普通会话使用当前根。历史根离线时会话仍可列出，但不能冒充空会话执行。
- 独立无项目会话使用 `workspaces/<会话短ID>`；短ID为随机小写字母和数字，
  创建时原子占位并对冲突重试，不随标题改变。侧聊、fork、子 Agent 共享父工作区。
- 新建 worktree 统一在 `worktrees/<工作树短ID>`，删除自定义位置选项和字段；
  已有/复用 worktree 保留路径，使用 Git 安全清理，不自动删除用户工作文件。
- 附件在导入时即绑定根，引用包含其归属，不能按“当前根”读取历史附件。
  已有会话导入附件使用会话根；未发送附件使用草稿归属，首次发送沿用该根。
- 全局日志、缓存、应用临时文件、浏览器下载使用当前运行根；窗口/语言等小型原生
  状态保留在配置入口。Windows WebView2 网站数据使用显式配置的运行根。
- 不可用、身份不符或不可写的根必须报错；不静默回退 C 盘。待切换目录启动失败时
  设置页明确显示失败与待切换目录，原活动根保持原身份。
- 删除会话记录不顺带递归删除工作区。归档不删除数据；共享工作区及活动子任务
  不能被后台清理。远程资源始终由执行宿主拥有。

持久化结构：

```text
<配置入口>/
  location.json
  engine.json                   配置、项目与会话索引，不保存完整消息/模型历史
  connection.json / server.json
  user-resources.json / skills/
  plugin-configuration.json
  native/                       窗口、语言等小型状态

<已登记运行根>/
  .gcode-root.json               根身份，缺失时不自动重建历史根
  sessions/<会话短ID>/<sha256>.json
                                消息、模型历史/上下文、目标、执行/排队、
                                会话改动、终端历史及最近请求前缀
  sessions/<会话短ID>/tool-results/
                                完整工具输出及超限命令流；随会话绑定原根
  terminals/<sha256>.json        无会话终端的输出
  workspaces/<会话短ID>/
  worktrees/<工作树短ID>/
  uploads/                      导入时绑定根的资源
  logs/ / cache/gcode/ / tmp/gcode/ / browser/ / downloads/
  tmp/processes/<ownerID>/       会话/终端子进程默认临时目录
```

会话正文采用不可变内容摘要文件；`engine.json` 的 `records` 映射是提交指针。
先写入并同步正文，再原子替换固定索引，失败不会覆盖已提交历史。索引提交成功后，
仅清理所属会话目录内旧摘要文件，不累计完整历史副本；不递归删除工作文件。
目标指令与验证记录、工具改动正文和终端输出不会进入配置索引。
旧版单文件格式直接报不支持，不添加迁移或双格式读写。

工具输出不属于全局缓存或临时目录，不随运行根切换搬动，也不由定时缓存清理删除。
落盘成功后才提交预览与路径；写入失败保留已经完成的工具结果并停止本轮，
不回放工具。模型可见的预览、内容摘要和用量锚点随 history/context 保存，
手动压缩使用保存的系统提示与工具定义，不从诊断轨迹重建业务状态。

写入保持同步提交：同一会话正文只编码一次，计算摘要后直接写入相同字节；
索引内容未变化且文件仍存在时不重复替换。History 与 Context 分别保存，不合并。
非 Windows 平台在替换后同步父目录；Windows 保持原有替换机制。
一个运行中的回合最多每 2 秒重写一次会话（`messagePersistInterval`），并在
回合结束、失败、取消与正常退出时同步保存；因此崩溃最多丢失该窗口内的执行
消息，已完成的回合不受影响。跨回合没有引入延迟提交。

窗口关闭先取消 UI 工作，在后台关闭业务核心。桌面从主窗口收到关闭事件
（或直接开始业务关停）起共用 5 秒退出时限，
覆盖终端回收、后台工作、最终保存、日志及配置锁清理；提前完成立即退出。
超过 5 秒自动结束桌面进程，退出码为 1，不弹确认；可能丢失未完成保存及终端尾部输出。
强退诊断尽力写入日志和 stderr，日志阻塞不会延长时限，不能保证该诊断已经落盘。
远程模式只关闭客户端，不终止远程宿主任务；无桌面服务入口的关停策略不因此改变。
终端输入、调整尺寸、清屏及已提交关闭的进程回收不再占用引擎全局锁，
同一终端的命令与尺寸提交仍按序执行。

桌面与无桌面服务的标准日志同时写 stderr 和 `logs/gcode.log`。单文件上限
8 MiB，最多保留 7 个归档，总计最多 8 个文件、64 MiB；归档最长保留 14 天。
日志写入或关闭失败直接在 stderr 报告。退出及原生重启前释放日志锁。
启动及每 15 分钟检查当前活动运行根，只清理应用拥有的数据：
`logs/gcode-*.log` 归档、`cache/gcode`（1024 文件、512 MiB、30 天）、
`tmp/gcode`（256 文件、128 MiB、24 小时）。不跟随符号链接，不清理下载、浏览器、
会话、工作区、工作树或其他名字的日志/缓存/临时文件。
子进程临时文件使用 `tmp/processes`，不进入该清理器；默认环境与用户显式覆盖规则见
[子进程临时目录](process-environment.md)。
本地桌面与服务由引擎维护运行根；远程桌面单独维护客户端本机运行根，退出时
取消并排空维护错误。远程会话与产物路径始终由宿主拥有，不加入客户端清理。

浏览器下载使用运行根的 `downloads`。MyGo 更新安装暂存目录仍在安装目标旁，
用于同文件系统的最终替换，正常退出通过 defer 清理；不能跨盘搬进运行根。
Windows WebView2 网站目录已接入 `browser`；macOS/Linux 网站数据仍由各平台
默认 WebView 数据仓库管理。Windows MyGo D3D11 shader cache 仍使用系统缓存目录，
上限 32 MiB。这些平台/框架路径尚不属于运行根控制范围。

验收覆盖：切换不复制、配置不搬动、旧会话续聊写旧根、新会话写新根、重启重建、
多次切换/切回、历史附件、离线历史根、身份不符、短ID与工作区隔离、派生会话共享、
远程断线与宿主重启，以及设置共享控件边界。真实原生和各平台支持单独记录。


## 已保存的统计投影

提交索引保存每个会话和运行的强类型统计汇总，以及应用用量的紧凑台账与报告。
这些数据由拥有执行记录的核心在数据变更时维护；会话记录与索引沿用现有的先写内容记录、
后原子提交索引的流程。统计不在 UI 首次打开历史时重建。
无法更新的历史存储根保留其上次已提交的统计，对依赖它的父级及应用报告使用同一已提交数据。
详见 [统计持久化与同类问题排查](metrics-persistence-2026-11-13.md)。

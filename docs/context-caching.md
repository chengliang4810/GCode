# 上下文压缩与缓存

2026-11-10 起，普通对话只追加已提交消息；删除旧式按轮次截短工具结果的微压缩。
必要的完整摘要压缩保留。实现参考成熟产品的前缀稳定性模式，没有引入新的运行时或依赖。

## 新结果的模型表示

- 不超过 32,000 字符的文本正常记录。
- 子 Agent 最终回复同样复用该边界；前台返回、后台通知与 `TaskOutput` 传递有界预览和
  完整文件路径，不额外调用摘要模型。文件归子会话原数据根所有，路径随运行持久化；
  详情见 [子 Agent](subagents.md#子任务结果长度与文件)。
- 超限文本先完整写入会话原运行根的 `sessions/<id>/tool-results`，
  再生成固定预览与文件路径。预览保留工具返回正文的开头和尾部；通过 Read 的 offset/limit 或
  有界文件处理命令继续读取。原工具本身的分页/范围限制仍有效。
- Bash 前台和后台任务的合并输出超过原 64 KB 内存上限后，继续流式写入同一会话目录；
  stdout/stderr 展示缓冲保持有界。流结束时同步并关闭文件，保留真实退出和取消语义。
  命令预览是有界缓冲的节选；完整流的尾部可从输出文件继续读取。
- 落盘路径不使用模型提供的工具 ID 拼接。目录通过受限根句柄访问，拒绝软链接目录，
  文件以私有权限创建。输出不进入自动清理的临时或缓存目录。
- 写入失败不伪造文件引用：已完成的工具及其返回结果仍记录，本轮停止，
  不为了恢复存储而再次执行工具。

这些决定发生在第一次向模型发送之前。后续请求、存储与恢复直接重用已提交表示，
不会重新按预览模板或新的阈值改写旧消息。
工具钩子的指令在预览之外完整保留。钩子替换或脱敏结果后不再返回原始输出文件路径。

## 去重范围

Read 按本次真实返回的内容摘要去重，不依赖文件名或 mtime 猜测内容未变。
图片按内容、MIME 和尺寸确认一致。用户附件和工具图片共用去重范围，
也移除同一条新消息里的重复图片；新消息保留图片标识、提问和原件路径。
只有原正文或原图片仍存在于当前模型上下文时，新结果才可以引用先前的消息。

引用消息不充当新的原始内容。完整摘要压缩移除原内容之后，再次读取会重新返回内容；
恢复会话从保存的上下文判断，不持有一个永不失效的“已经读过”缓存。
工具照常执行，只有模型输入表示去重；不会跳过真实读取或有副作用的工具。
去重引用另有宿主内部的内容标识，不发送给供应商。完整摘要或分层折叠若移除了原图、
却保留了引用该图的消息，会在提交新上下文前把所需图片补到保留窗口中，
避免最新提问在自动压缩后只剩一个失效引用；原执行历史和归档不被改写。

## 图片原件与模型表示

导入的图片原件保存在所属数据根的 `uploads`，不改写原文件。
用户图片在运行后台、首次模型请求前复用 Read 的解码、方向校正和编码流程：
最长边不超过 2048 像素，单图 Base64 不超过 4 MiB；优先保留 PNG 和透明度，
不透明图片超预算时尝试 JPEG，再按需缩小尺寸。
模型输入包含原件路径以及发生转换时的原始/展示尺寸；Read 原件也使用相同预算，
路径用于再次读取和本地文件处理，不代表远程模型能直接访问宿主文件。

准备完成的消息先提交到执行历史和有效上下文，再发请求；重试及重启复用该表示。
旧历史不因新预算而批量改写，不按时间删除图片，也不增加微压缩路径。
单图预算不是整轮媒体总字节上限；多张不同图片仍会累计，提示缓存也不代替上传。

## 自动与手动摘要

自动压缩使用最近一次真实供应商 input/output usage 作为锚点，并估算新增消息。
`model.Usage.Input` 已含缓存输入，不再另加 Cached。
按模型和历史内容指纹验证基线；历史相同但提示或工具改变时，只估算提示和工具的差额。
没有旧提示大小时保守计入整个新提示。缺少历史指纹的既有 Chat 会话可用已保存的逐消息请求指纹
离线验证；证据不足、模型变更或历史不匹配时使用本地估算。
容量未知时不自动触发。

触发前从容量中扣除正常请求实际发送的输出上限，再留出下一步工具结果增长空间；
正常请求最多允许输出 64,000 Token，摘要请求最多 16,000 Token，两者均遵守更低的模型配置。
未知输出上限时采用受限的窗口比例预留。阈值是执行保护，不是供应商实测 token 数。

生成摘要时沿用主对话的系统提示、思考配置和原消息前缀，在尾部追加摘要任务。
摘要请求不发送工具定义；历史工具调用及其结果仍作为摘要素材保留，正常对话的工具不受影响。
普通摘要只有一次模型调用。分层上下文折叠要求摘要去除首尾空白后为 1–8000 个字符，
且确实缩小所选历史；校验不通过时，携带具体原因与字符数重新生成，最多三次模型调用。
重写沿用同一段原始历史，不截断摘要。分层自动压缩只折叠达到预算所需的完整历史区间，
在触发线下额外留出一份增长预留后停止。每段完成后保存估算、历史和原文归档。
普通及分层摘要都会把折叠区间中的用户原话独立带入后续摘要；这些原话属于历史任务，不是新的操作授权。
两种模式还保留少量近期的定位和验证结果原文。达到触发线时，先估算缩短已归档的旧工具预览是否足够；
只有一次能腾出所需空间才应用，否则直接做摘要。当前任务、错误输出和图片不作轻量清理。
近期受保护输入本身过大时直接报错。明确的供应商超窗错误允许一次补救压缩，不把网络超时或限流当作超窗。
后续段失败不回滚已保存的段；失败段仍保留原文。不执行摘要返回的工具调用。
每次摘要请求最多 90 秒，自动压缩整轮最多 6 分钟。剩余时间不足一次摘要预算时，不启动下一段。
摘要替换完整前缀，保留最近完整工具交互；输入归属 ID 和保留消息的私有续接状态继续保存。
手动 `/compact` 使用会话保存的最近请求前缀，业务状态不从轨迹文件恢复。

**原始模型请求诊断（默认关闭）。** 在「设置 → 通用」中开启「记录原始模型请求和响应」。
新请求保存在执行模型请求的宿主当前数据目录下的 `model-wire/`（默认 `~/.gcode/model-wire/`）。
切换数据目录并重启使其生效后，新录制写入新目录，旧文件留在原处。
每次请求尝试分别保存 `request.json`（脱敏策略处理后实际发送的请求体）、
`response.body`（HTTP 客户端收到的响应体，应用解析和恢复脱敏占位符前）和 `metadata.json`。
捕获目录名包含调用 ID 和重试序号，可与轨迹对应。`responseComplete: false` 表示未读到
完整响应，例如连接中断或解析退出后补读超过 3 秒。请求认证头不保存。
文件可能含源码、对话、附件或响应中的秘密；捕获不自动清理，也不受普通轨迹容量限制。
排查完成后关闭开关，按需清理捕获目录。不记录启用前的请求，关闭也不会删除已录制文件。

Anthropic Messages 使用标准内容块缓存断点；摘要指令本身不写入消息级缓存。
OpenAI Chat/Responses 不发送 Anthropic 缓存字段。生成摘要可能复用旧前缀，
但摘要替换历史后的对话仍需建立新前缀，不能保证缓存命中或费用下降。

## 观测与验收

轨迹区分完整 wire body 摘要、系统/工具/请求参数/目标变化、消息前缀变化，
以及图片字节量、上传结束、响应头到达、首个输出和上游请求 ID。
缓存标记位置变化不被当作正文改写；真实请求体的任何变化仍反映在 body SHA-256。
主动压缩和摘要的预期重建单独记录；无 usage 的失败不作为零命中。

确定性测试覆盖三协议真实 HTTP 编解码与 Go 文件工具、稳定预览/去重、
摘要配置保留、超限命令流、存储失败、会话重启、数据根切换及目录软链接拒绝。
这些测试使用本地供应商夹具；实际供应商命中率、价格、延迟变化需要运行新版本后另行观测。

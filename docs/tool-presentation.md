# 会话工具记录

工具协议名称用于模型调用；中文动作、摘要与详情由共享的会话展示投影提供。
本机与远程客户端使用相同的 `contracts.ToolCall`，桌面不解析工具协议来补做业务状态。

| 工具 | 动作 | 摘要 |
| --- | --- | --- |
| Edit / Write | 编辑 / 写入 | 文件名，随后显示本次调用增加、删除的行数 |
| TaskOutput | 读取任务结果 | 任务名，缺省使用命令行；都没有时只显示动作 |
| TaskStop | 停止任务 | 任务名，缺省使用命令行；都没有时只显示动作 |
| Skill | 使用技能 | 实际调用的技能名 |
| goal_read | 读取目标 | 本次读取的目标内容 |
| ListDirectory | 列出目录 | 目录路径 |
| WebFetch | 读取网页 | 请求地址 |
| WebSearch | 搜索网页 | 查询内容 |
| Agent | 启动智能体 | 委派任务描述；成功启动后显示子智能体记录 |
| MCP 工具 | 调用工具 | 插件、服务名称与工具可读标题 |
| ContextStatus | 查看上下文状态 | 无额外摘要，原始参数与输出保留在详情 |
| CompressContext | 压缩上下文 | 同上 |
| SearchContext | 搜索历史上下文 | 同上 |
| DecompressContext | 读取归档上下文 | 同上 |

MCP 标题按 `title`、`annotations.title`、`name` 的顺序选择。
展示名称不参与模型工具 schema 或 `tools/call`，原始工具身份保持独立。
任意 MCP 参数与输出仍可在详情中检查，不推测未知外部工具的业务语义。

## 名字不显示编号

工具参数里只有 `task_id`、`run_id` 这类标识，而工具行读给用户看的是名字。
核心在事件边界把标识换成名字，桌面只投影，不自己查业务状态：

- `TaskOutput`、`TaskStop`：先找同名子会话的标题，再找本会话后台命令的描述；
  任务运行中也一样，不必等到工具结束才有名字。
- 工作流工具：按 `run_id` 找运行名；运行没有名字就留空。
- 读不到名字时摘要留空，行只显示动作词（如“读取任务结果”），不拿编号顶替。
- 活动行的读屏名字同样只用动作词与可读描述，块编号不念给用户；流式思考行用
  第一段已写完的文字做名字，行名不随展开或追加而跳动。

对应实现是 `internal/engine/tool_names.go` 与
`internal/desktop/transcript.go` 的活动行命名；编号仍保留在 `ToolCall.TaskID`
和原始参数里，详情可以查看。

成功完成的文件修改直接使用 `ToolCall.Diff.Additions/Deletions`，
在文件名后显示绿色 `+N`、红色 `-N`，包括实际的零行计数。
计数属于该次工具调用，不使用项目或会话的累计变更。
运行中、失败或没有 diff 数据时不显示计数，不把缺失数据当作零。
长文件名优先收缩，计数保持完整；文件名继续打开文件，行本身继续展开 diff。

已知内置工具的详情展示动作对象和实际输出；目标详情展示本次读取的目标、
状态、用量、预算、下一步与原因。目标快照独立克隆，不随之后的目标编辑变化。
读取失败保留原始错误与参数。子智能体取消请求显示“已请求停止”，
不会在进程或执行者退出前显示“已停止”。

网页搜索在最终的会话工具集合中按设置加入，避免被会话运行工具替换。
只读子智能体继续使用其受限的文件工具集。

文件修改有 diff 时，展开内容只展示差异视图及邻近代码上下文，不再重复工具参数、原始输出或文件路径；隐藏未修改行数的展开条及其占位。没有 diff 的失败记录继续展示错误详情。

## 工具分组与标签页提示

工具分组的展开箭头与正文左对齐，分组标题保留缩进；分组标题、组内层级与
连接线的相对几何保持稳定，不随内容长度变化。

标签页的标题提示只来自该标签自身确实存在的详情：文件标签用真实路径，
浏览器标签用当前已导航的 URL，轨迹标签用标题与记录 ID。没有对应详情的标签
（侧聊、Diff、终端、子智能体等）不生成标题提示，也不能拿相邻标签的标题冒充。
对应实现是 `internal/workbench/tabs.go` 的 `tabDetail`，图标透明度、脏标记与
选中态规则由 `internal/workbench/tabs_file_icon_test.go` 与
`internal/workbench/tabs_style_test.go` 覆盖。

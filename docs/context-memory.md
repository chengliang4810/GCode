# 分层上下文压缩

设置入口：**设置 → 通用 → 分层上下文压缩**。默认关闭。
设置保存在 `settings.general.hierarchicalContext`，从下一次 Agent 运行或手动压缩生效；
不会改变已经运行中的任务。关闭时使用原有窗口预算与整段前缀摘要路径，
不注入上下文管理工具或提示。已有摘要档案仍保留，重新开启后可检索。

这是一套借鉴 billion-context 思路的原生 Go 实现，不运行它的 TypeScript
代理，也没有把桌面与本机核心改成网络调用。桌面、本机和远程服务使用同一核心；
会话状态、压缩和工具执行属于运行任务的宿主。

## 模型视图与原始档案

- `model.Message.ContextRef` 是宿主生成的稳定引用，只用于持久化及核心内处理，
  三种供应商协议不会序列化该字段。原消息文本、工具参数和签名推理载荷不插入标签。
- 核心保存独立的 `ContextMemory`，与 `sessionDisk.Context` 在同一会话记录内提交。
  摘要块包含 ID、层级、摘要和被覆盖消息的完整结构；高层摘要通过原消息中的
  `ContextRef` 保留子块关系。块引用不复用。
- 第一条消息、最新的人类输入、至少八条近期消息和完整工具调用/结果边界受保护。
  模型提出的范围与自动压缩范围使用同一折叠校验。
- 一次折叠必须实际减少估算 token，拒绝空摘要、超过 8000 字符的摘要和不合法范围。
  保存失败时不应用新的上下文投影。
- 累计约 50K **估算的可见消息 token** 增长后提醒模型整理已完成阶段。
  达到窗口压力阈值时核心主动生成分段摘要；一段约 12K 估算 token，
  不切断单个完整工具交换，因此特别大的单个交换可以超过这一目标。
  当相邻前缀摘要达到四块时合并到更高层，层级最高标记为三级；
  三级仍能继续归并，原文档案不会被摘要替换。
- 预算压缩最多连续执行 32 次，仍不能降低到阈值或者只剩受保护内容时明确失败，
  不通过截断当前任务或丢掉原文来伪造成功。原有 PreCompact、PostCompact、
  SessionStart 自动/手动压缩生命周期继续执行。

## 模型工具

| 工具 | 用途 |
| --- | --- |
| `ContextStatus` | 分页查看当前消息引用、估算用量和候选范围；每页最多 40 条 |
| `CompressContext` | 模型选择首尾引用并提供摘要，核心验证并提交 |
| `SearchContext` | 对摘要、归档原文和当前消息做大小写不敏感的字面检索；每页最多 20 条 |
| `DecompressContext` | 读取块的直接子引用，或按引用分页读取历史消息正文与工具参数 |

恢复的内容作为普通工具结果返回，不作为新的用户要求或系统规则。
文本页默认 4000 字符，最大 8000 字符，按 Unicode 字符分页。
图片原数据保存在档案中；当前工具仅返回图片数量，不展开图片。
历史隐藏推理与供应商 continuation 信封不通过读取工具公开。
工具遵守现有 PreToolUse/PostToolUse 钩子与有效工具限制；
模型主动折叠是 `CompressContext` 工具操作，通过工具钩子管理。

## 会话生命周期与边界

- 手动压缩同样遵循开关；开启后只压缩一个历史段或合并一个摘要前缀。
- 重启和懒加载恢复块、原文及引用；普通分叉获得独立档案副本。
- 侧聊只复制其快照能引用到的块及子块，不通过检索暴露父会话后续工作。
- 输入拒绝或待执行输入回退需要从完整历史重建上下文时，同时清除旧摘要索引，
  避免通过旧档案重新发现已经被拒绝的内容；完整有效历史仍由宿主保留。
- 开启前由旧压缩产生的摘要不会自动反推成可恢复块，也不做历史数据迁移。
- 本版本使用现有会话 JSON 持久化；完整执行历史与压缩档案会有额外存储开销。
  它没有实现十亿级历史的独立分块存储或全文索引，不应将功能回归视为该规模的验证。

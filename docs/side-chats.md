# 侧边聊天与分支聊天

右侧面板空态和顶部 `+` 菜单中的“侧边聊天”都创建一个独立子会话。
入口复用现有面板控件，只显示名称，不增加说明或副标题。

每次显式创建都会生成不同的会话 ID，并记录父会话和创建请求 ID；
同一创建请求重发仍只产生一个子会话。新标签激活并聚焦自己的输入框，
主会话的选中状态、草稿以及其他侧聊草稿保持不变。

业务核心复制创建时父会话的模型历史及已压缩上下文，深拷贝后独立持久化。
父任务正在运行时，复制边界止于最近已接受的人类输入，
不把该输入之后尚在执行的回答、工具调用或等待请求交给侧聊继续执行。
创建后的父会话新消息不再自动同步到子会话。

继承历史只用于模型上下文，不显示在侧聊时间线中；
侧聊界面从空白开始，只显示它自己的新消息。
模型选择、思考强度和工作目录继承父会话，后续独立配置和执行。
父会话的目标、任务队列、正在执行的任务及固定、归档、未读和完成状态不复制。
新侧聊没有自己的用户输入时，不能通过重试去接续父任务。

侧聊系统提示明确要求：父历史只供参考，不自动继续父任务，
只处理侧聊中的新问题，只有用户在侧聊明确提出要求时才修改工作区。
提示在构建模型请求时生成，重启后同样生效。
这是模型行为约束；侧聊仍有正常工具能力，并与父任务共享同一个工作目录，
文件修改会影响双方，不提供文件系统隔离。

桌面到本机核心仍直接使用 Go 接口。远程连接沿用同一个业务核心，
不在客户端复制上下文或增加另一套执行逻辑。
继承上下文会增加子会话的存储及后续请求的上下文用量；
界面空白不代表请求的模型历史为空。

核心测试覆盖独立快照、运行中边界、深拷贝、重启及三种协议的请求；
桌面组件测试覆盖中英文、深浅主题、900/1600 宽度、空态与 `+` 多开、
草稿及选择隔离和原有子会话入口。原生桌面测试
`TestDesktopLocalSideChat` 使用真实本机核心及本地 HTTP 模型夹具，
分别验证浅色英文和深色中文窄窗中的创建和发送。
这些测试不代表真实外部供应商、系统输入法或视觉一致性验收。
原生证据及深浅主题截图位于
`output/side-chat-context-native/20261030-155932-3289309110/`。
本轮全仓 Go 测试、共享控件边界检查、Go vet、MyGo vet、
普通 Windows 桌面构建和 Linux amd64 无桌面服务交叉编译均通过。

## 分支聊天

左侧会话列表的会话右键菜单提供“分支聊天”和“在新工作树中分支聊天”：
两者都继承父会话的模型历史和已压缩上下文，但创建的是顶层会话，
真实出现在左侧列表中，不挂在父会话之下，也不占用右侧侧聊面板。

- 分支会话完整复制可见时间线：消息、工具块和问答都换成新的消息 ID，
  并清空流式标记，因此后续在分支里的追问不会改写父会话的记录。
- 父会话的目标、任务队列、正在执行的任务及固定、归档、未读和完成状态不复制，
  与侧聊一致。
- 与侧聊的两点不同：分支不是 `SideChat`，因此不追加“父历史只供参考”的系统提示；
  分支有自己的用户输入，可以正常重试。
- “在新工作树中分支聊天”要求父会话属于已探测到 Git 的项目：
  从当前 HEAD 新建工作树和新分支（`newWorktree` 检出计划），
  工作树登记到该项目下，父会话的工作目录与分支保持不变。
  没有项目的会话、或项目不在 Git 上时该项禁用，普通“分支聊天”仍共用父会话目录。

`session.branch` 命令与 `message.send` 的检出计划共用同一套 Git 准备工作：
准备阶段在状态锁外执行，创建被拒绝或失败时清理自己新建的工作树，
不会改动父会话或已存在的工作树。界面用创建请求 ID 对账，
迟到的完成结果不会抢占用户已切换到的其他会话。

核心测试 `TestBranchCopiesTranscriptAsTopLevelConversation`、
`TestBranchIntoNewWorktreeTakesOwnCheckout` 和
`TestBranchIntoNewWorktreeRequiresProject` 覆盖顶层身份、时间线复制、
重建消息 ID、请求幂等、真实 Git 工作树与无项目拒绝；
mock 与桌面组件测试覆盖菜单两项、禁用条件、草稿保护和列表出现。
原生桌面分支聊天尚未录制证据，列为待验收项。

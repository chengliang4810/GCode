# 侧边聊天

右侧面板空态和顶部 `+` 菜单中的“侧边聊天”都创建一个独立子会话。
会话信息卡移除“新建分支聊天”，保留已有子会话入口及普通分叉。
入口复用现有面板控件，只显示名称，不增加说明或副标题。

每次显式创建都会生成不同的会话 ID，并记录父会话和创建请求 ID；
同一创建请求重发仍只产生一个子会话。新标签激活并聚焦自己的输入框，
主会话的选中状态、草稿以及其他侧聊草稿保持不变。

业务核心复制创建时父会话的模型历史及已压缩上下文，深拷贝后独立持久化。
父任务正在运行时，复制边界止于最近已接受的人类输入，
不把该输入之后尚在执行的回答、工具调用或等待请求交给侧聊继续执行。
创建后的父会话新消息不再自动同步到子会话。

继承历史只用于模型上下文，不显示在侧聊时间线中；
侧聊界面从空白开始，只显示它自己的新消息。
模型选择、思考强度和工作目录继承父会话，后续独立配置和执行。
父会话的目标、任务队列、正在执行的任务及固定、归档、未读和完成状态不复制。
新侧聊没有自己的用户输入时，不能通过重试去接续父任务。

侧聊系统提示明确要求：父历史只供参考，不自动继续父任务，
只处理侧聊中的新问题，只有用户在侧聊明确提出要求时才修改工作区。
提示在构建模型请求时生成，重启后同样生效。
这是模型行为约束；侧聊仍有正常工具能力，并与父任务共享同一个工作目录，
文件修改会影响双方，不提供文件系统隔离。

桌面到本机核心仍直接使用 Go 接口。远程连接沿用同一个业务核心，
不在客户端复制上下文或增加另一套执行逻辑。
继承上下文会增加子会话的存储及后续请求的上下文用量；
界面空白不代表请求的模型历史为空。

核心测试覆盖独立快照、运行中边界、深拷贝、重启及三种协议的请求；
桌面组件测试覆盖中英文、深浅主题、900/1600 宽度、空态与 `+` 多开、
草稿及选择隔离和原有子会话入口。原生桌面测试
`TestDesktopLocalSideChat` 使用真实本机核心及本地 HTTP 模型夹具，
分别验证浅色英文和深色中文窄窗中的创建和发送。
这些测试不代表真实外部供应商、系统输入法或视觉一致性验收。

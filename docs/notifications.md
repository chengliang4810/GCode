# 桌面通知

本机和远程会话共用桌面的类型化状态观察器。启动快照只建立基线；新任务完成、
需要输入、运行错误及远程连接断开时产生通知，同一状态不会随渲染或重复快照重播。
中断任务不算完成；自动子智能体的独立运行不重复产生系统通知，由父会话汇总。
用户主动创建的侧聊和分叉会话保留完成、待回答及错误通知。

“桌面通知”控制系统横幅，“仅在后台时”按主窗口焦点限制横幅。
“会话声音”独立控制音效，下方三项分别控制完成、需要输入及错误/断线声音。
关闭横幅仍可保留声音；开启横幅不强制播放系统默认声音。
修改设置只影响之后发生的事件，不补发此前已完成的任务。

系统横幅调用固定 MyGo 的原生通知 API，声音调用 MyGo audio；
Windows 使用通知区域系统横幅及 WASAPI，macOS 使用 Notification Center，
Linux 使用桌面 DBus 通知服务。操作系统通知权限、免打扰设置和音频设备决定最终
能否显示或发声；失败记录到应用日志。没有桌面环境的服务入口不初始化这些组件。
队列、音频和通知权限等待都归窗口生命周期管理，窗口关闭取消等待和待处理通知。
桌面不会因为通知或远程断线取消宿主已经接受的任务。

`TestDesktopNotifications*` 使用注入的通知接收器，覆盖实际状态接线、去重、
前后台条件、独立声音设置及关闭取消，不向用户发送测试横幅或声音。
远程断线/恢复使用本地 HTTP 测试宿主验证；框架回归覆盖取消通知授权等待及迟到授权。
这些测试不代表系统通知已在真实 Windows/macOS/Linux 桌面上逐一验收。

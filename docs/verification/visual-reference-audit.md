## 具体差距

### 1. 品牌锚点的层级弱于 T3

T3 的左上品牌区使用明显的蓝色视觉场承载图标和 `T3 Code`，与下面的搜索、项目和会话导航形成清楚的第一层分区。GCode closure 的左上只显示近黑表面上的灰色 G 图标、`GCode` 文字和蓝色新建按钮，品牌区与导航共用同一暗色背景，品牌锚点更弱，蓝色主要落在新建动作而不是品牌层级上。

证据：两张图的左上区域；`PRODUCT.md:30-32` 的 T3 最低标准；`DESIGN.md:148-155` 的近黑表面和层级原则。这里记录的是品牌层级差距，不推断必须复制 T3 的渐变或图形资产。

### 2. 右侧 Diff 表头堆叠更多，首屏内容密度低于参考

T3 的右栏以单一 `Diff` 标题、加号和紧凑工具控件组成主表头，文件内容较快进入视野。GCode closure 先放置“资源 / 文件 / Diff / 终端”标签、关闭按钮和多枚图标控件，再放置“项目 Diff”和分支信息，随后才进入文件和 hunk 内容。两层导航与上下文信息同时存在，使右栏顶部更像工具栏堆叠，首屏 Diff 内容开始得更晚。

证据：两张图的右栏顶部；`DESIGN.md:207` 对右栏职责和最小宽度的定义；`DESIGN.md:250-252` 对文件/hunk 分组和 Diff 内容的定义。此项指出密度和层级关系，不要求删除资源、文件或终端入口。

### 3. 运行中 composer 的同级控件较多，主要动作层级不如参考收敛

T3 参考图的底部输入表面以文本输入和少量尾部动作构成单一操作焦点。GCode closure 的运行状态同时呈现“纠正 / 队列”、`OpenAI API` Select、“完全访问”复选框、停止圆钮和发送圆钮；这些控件都处于同一底部横向区域，视觉重量接近，发送、停止、模式、模型和权限的优先级需要用户同时解析。

证据：两张图的 composer；`DESIGN.md:238-240` 要求这些控件位于单一尾部行；`docs/verification/visual-v2-review.md:18`、`:84` 已将停止/发送双动作判为产品适配，但指出状态和间距仍可更明确。此项不否定停止和发送两个产品动作，也不提出删除控件。

### 4. 路径/分支上下文在 GCode 中重复出现，辅助文字层级偏弱

GCode closure 的中间表头同时显示会话标题、`/Users/demo/Projects/gcode` 路径和 `gcode · work/settings-fix` 分支信息；右侧 Diff 区又单独重复 `work/settings-fix`。这些上下文文字使用较小的弱化颜色，重复位置多但层级差异有限。T3 参考图的中间表头以一条紧凑的项目/任务标题为主，右栏没有同样明显的分支重复，因此扫描主任务时更直接。

证据：两张图的中间表头和右栏上下文行；`DESIGN.md:175` 的辅助文字规则、`:207` 的三栏职责以及 `docs/verification/visual-v2.md:32` 对标题/路径/分支两行表头的现状记录。路径和分支仍是 GCode 的产品上下文，本项只记录重复和对比度层级，不主张移除它们。

### 5. 模型 Select 的边界比周围控件更重，表面语义尚未完全统一

GCode closure composer 中的 `OpenAI API` Select 使用明显的矩形边界和独立暗色表面；相邻的“纠正 / 队列”分段控件和蓝色发送圆钮采用不同的形状与边界语言。T3 参考图的同类顶部/底部控件更接近低反差、胶囊化的统一表面。GCode 的 Select 仍可用，但在视觉上成为一块较重的边界，削弱了 composer 单一表面的连续性。

证据：两张图的底部控件；`DESIGN.md:118-123` 对 Select 的 surface、border、radius 和高度规定；`docs/verification/visual-v2-review.md:21`、`:83` 已记录原生 Select 默认边框比参考更重，并将其列为精致度上限而非功能缺陷。此项是控件一致性差距，不改变模型选择功能。

## 结论边界

当前 GCode closure 已完成既有两项确定性修复的技术核验，但以上五项仍是与 T3 最低视觉标准相比可以直接观察到的候选差距。它们不足以支持“用户已认可”或“视觉交付达标”的结论；本审计也没有把这些发现转换为新的 UI 实现任务。

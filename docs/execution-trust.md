# 执行信任边界

2026-11-16 确认：GCode 采用受信宿主执行模型。

- 工具、Hook、已安装并启用的插件及 MCP 使用宿主 OS 用户的权限运行。
  安装、启用和配置这些执行组件意味着信任其代码与目标服务。
- 远程 bearer token 授权控制该宿主；它不是只读凭据，也没有按项目分配权限。
  通过认证的客户端可以浏览宿主目录、配置模型和执行任务。
- 用户配置的模型、MCP 与网站图标服务可以位于回环地址或私网。
  不引入统一私网禁用规则，以免阻断本机服务与内网服务。
- Write/Edit 的工作目录边界、托管资源校验及工具默认环境白名单继续生效，
  但不构成 OS 沙箱。不会据此声称 Bash 或插件无法访问宿主用户文件。
- 插件明确配置的环境变量展开、MCP `Env` / `Headers` 和
  `CLAUDE_PLUGIN_OPTION_*` 是向受信组件传递配置的通道。
  不承诺对同 OS 身份运行的程序保密。
- 供应商凭据的显式 reveal、日志和模型上下文的敏感值脱敏、
  非回环远程连接的 TLS 策略仍有各自职责。受信执行不等于应将凭据
  无意带入网站图标请求、诊断日志或模型提示。

不将“缺少系统沙箱、危险命令分类或插件首次启动确认”列为当前产品的待修缺陷。
原生视觉一致性优化仍保持暂停。

# 长会话性能

## 实现范围

- 主对话和侧聊使用同一套增量投影。来源快照不变、流式事件更新最后一条回复且行身份和分组形状不变时，只投影该回复，复用历史行和消息定位轨。合并了多轮模型请求的回复仍保留完整内容。首个正文块、行形状改变、快照替换或存在尚未确认的发送投影时，走常规投影。
- 普通行引用不可变的消息块。工具结果没有替换已有调用时不复制块列表；发生替换时仍保留首次出现的位置和 ID。
- 不改变会话存储、上下文、列表估高、Markdown 分段或滚动交互。基准中的冷打开成本主要来自全量行投影与软件绘制，尚不能证明需要修改 Markdown 或存储。

## 基准

macOS Intel i7-9750H、Go 1.27.3，使用 `ui.Tester`、固定 1320×880 窗口和同一组模拟记录。采用 5 次运行的中位数，MB 为十进制、表示每次操作累计分配量，不是进程常驻内存。

| 场景 | 耗时（前 → 后） | 分配量（前 → 后） |
| --- | ---: | ---: |
| 1000 轮，流式增量 + 渲染历史位置 | 14.76 → 4.75 ms | 6.91 → 0.64 MB |
| 1000 轮，冷投影 + 首屏 | 35.26 → 28.81 ms | 12.29 → 8.11 MB |
| 100 轮，流式增量 + 渲染历史位置 | 4.47 → 4.21 ms | 0.51 → 0.24 MB |
| 100 轮，冷投影 + 首屏 | 20.45 → 20.65 ms | 3.33 → 2.92 MB |

现有滚轮基准没有显示一致的耗时回退。小会话和滚轮耗时波动较大，不据此判断帧率。

```sh
go test ./internal/desktop -run '^$' -bench '^BenchmarkTranscript(LongSession|Wheel)$' -benchmem -benchtime=140ms -count=5
```

冷打开从已加载的消息开始，重置列表状态和投影缓存，不包含磁盘读取与解码。两个基准都不包含模型请求、远程传输和原生 GPU 呈现。

## 回归边界

组件回归覆盖长历史、续写轮次、紧凑模式和侧聊行身份，并对照完整投影比较正文、搜索命中和定位轨。历史阅读位置和返回最新在深浅主题、900/1320 DIP 下验证。原生滚动测试使用信息卡现有控件的稳定 key，而不是已移除的 `SIDE CHATS` 标题。

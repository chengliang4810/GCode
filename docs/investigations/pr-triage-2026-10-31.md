## 未合并：维护者理由与我们的资料

### #956 `OnFilesDrop` — 关闭

维护者：`DroppedFiles` 已覆盖；drop 会立即请求一帧，不需要回调；希望输入保持轮询式
（像 `Clicked`、`Hovered`）。

应用侧：原为 `internal/desktop/composer_surface.go` 一处
`composer.OnFilesDrop(p.onFilesDrop)`。**已按上游建议改写**：每帧读取
`composer.DroppedFiles()`，drop 会请求一帧，路径在下一帧到达；本地
`OnFilesDrop` 补丁随之删除。

### #959 `CollapsibleBaseWithAnimation` — 关闭

维护者：不想给每个控件都加 `WithAnimation` 变体；`CollapsibleBase` 是基础控件，
需要其他时长时用 `AnimateTo` 构建面板。

应用侧：3 处使用，侧栏分组需要 140ms（默认 200ms）。可以作为后续迁移到
`AnimateTo` 的例子；目前保留本地补丁，并在
`docs/tool-fold-motion.md` 记录行为。

### #964 `OnHover` — 关闭

维护者：`Hovered` 只在悬停状态改变时请求帧，不存在每帧轮询的浪费；希望输入保持轮询式。

应用侧：原为 3 处（`annotation_chips.go`、`model_picker.go`、`transcript.go`）。
**已按上游建议改写**：每帧读取元素的 `Hovered()`，模型列表行直接据此移动游标；
标注 chip 与 transcript 行用应用自己的状态记录进入与离开
（`App.hoveredAnnotation`、既有的 `transcriptHover` 映射）；本地 `OnHover`
补丁随之删除。

### #965 应用级动效覆盖 — 关闭

维护者：减少动态是用户的决定，不希望应用覆盖它。

应用侧：这是**应用内的用户设置**，不是静默覆盖系统：
`internal/desktop/motion.go` 把“设置 → 通用 → 动效”（system / full / reduced）
映射到 `SetMotionPreferences`，并把 `SmoothScrolling` 设为 false 以匹配参考实现的
滚轮行为。对维护者可以补充的实例：

```go
// 用户在应用设置里明确选择“完整动效”或“减少动效”。
c.SetMotionPreferences(&ui.MotionPreferences{
    Motion:          ui.MotionFull, // 或 MotionReduced / MotionSystem
    SmoothScrolling: false,
})
```

如果上游仍不接受应用级覆盖，替代方案是应用只驱动自己的动画，但 MyGo 内置的
列表跟随、页面过渡、Markdown reveal 和折叠动效无法统一跟随该设置。当前保留本地补丁。

### #966 `SnapToWindow` — 关闭

维护者：`AttachTo` 已经会翻转并夹紧 popover；如果仍被裁切，请开 issue 并附复现。

我们按维护者的说法做了最小验证（`ui.NewTester`，200×200 窗口，`AttachTo`）：

- 窗口中部、面板 100×180 附着在触发器下方：`AttachTo` 把高度压到 90，底边正好 200，
  未越界。
- 左边缘、面板 180×60 附着在触发器左侧：`AttachTo` 把宽度压到 160，右边缘正好 200，
  未越界。

因此**无法用纯 `AttachTo` 复现裁切**。应用中的 `SnapToWindow` 主要用于
`AttachAtPoint`（本仓库第 15 项补丁新增的点定位 API）和固定尺寸面板：
`composer_prompt.go:315`、`composer_footer_usage.go:358`、`composer_footer_git.go:434`、
`model_picker.go:198`。如果上游愿意接受点定位面板的贴窗需求，可以再开 issue；
否则维持本地补丁，不把 `AttachTo` 的现有行为误报为缺陷。

### #968 Markdown 固定 DIP 行高 — 关闭

维护者：DIP 行高不跟随用户文字缩放，放大文字会重叠，标题还会继承正文行高；
`LineHeight: 1.7` 已经表达 25.5/15。

应用侧：Markdown 使用 `Theme.LineHeight` 多处；精确 DIP 行高主要用于富文本 composer
和 `internal/linkui/markdown.go` 的测量。接受维护者对 Markdown 主题的结论；
`markdown.Theme.FixedLineHeight` 仍作为本地补丁服务设计稿逐项对齐。后续可评估把
Markdown 侧迁移到倍数行高，从而再缩小第 4 项补丁。

## 上游缺陷：Windows UIA `ProviderOptions`

第 7 项本地补丁不是重复上游，而是在修正上游取值。证据：

- 本机 Windows SDK 10.0.26100 `UIAutomationCore.h`：
  `ProviderOptions_ClientSideProvider = 0x1`、`ProviderOptions_ServerSideProvider = 0x2`、
  `ProviderOptions_UseComThreading = 0x20`。
- 上游 v0.7.4 `internal/windows/surface_access.go` 返回 `0x1 | 0x20`，注释却写
  “ServerSideProvider, UseComThreading”。
- 本仓库补丁返回 `0x2 | 0x20`（`0x22`），并保留 COM 契约测试断言 `0x22`。

已向上游提交独立 PR：[#1007 windows: advertise the server-side UIA provider](https://github.com/egoist/mygo/pull/1007)
（fork 分支 `fix/uia-provider-options`，提交 `a1eb92d5`）。该 PR 与已关闭的
6 个 PR 无关，不涉及设计取舍。

## 维护者建议的可采纳性评估

维护者在关闭 PR 时给的建议，能否用上游组件/技术达到同一效果，逐项判断如下：

| 本地补丁 | 上游替代方案 | 能否等价 | 建议 |
| --- | --- | --- | --- |
| 02-hover `OnHover` | `Hovered()` 轮询（变化时会请求帧） | 可以；应用内保存上一帧 hover 状态并比较即可 | **已采纳**，本地补丁已删除 |
| 03-files-drop `OnFilesDrop` | `DroppedFiles()` 轮询 | 可以；drop 会立即请求帧，单处调用 | **已采纳**，本地补丁已删除 |
| 04-markdown-line-height | `Theme.LineHeight` 倍数 | Markdown 可以；富文本仍需精确 DIP | **部分采纳**：Markdown 侧改为倍数，富文本保留第 8 项 |
| 05-snap-to-window | `AttachTo` 已翻转/夹紧 | 普通附着可以；点定位面板不行 | 普通场景采纳 `AttachTo`；点定位场景保留 |
| 11-collapsible-animation | 用 `AnimateTo` 自建面板 | 可以，但要重写折叠面板的展开/收起与内容移除 | 可采纳，工作量中等；建议后续单独做 |
| 01-motion | 应用自己的动画 | 不能完全等价；MyGo 内置列表/页面/Markdown/折叠动效读引擎偏好 | 保留 |
| 06-input-display-text | 无上游等价 API | 不能 | 保留 |
| 07-windows-uia-provider | 上游当前实现有误 | 不能（上游值本身错误） | 保留并已提 #1007 |
| 08-richtext-composer | 无上游等价 API | 不能 | 保留 |
| 09/10/12/13/14/15/16/17/18 | 无上游等价能力或仅为渲染细节 | 不能 | 保留 |
| 20-split-drag | 无上游等价能力（主副本新增） | 不能 | 保留 |

结论：维护者的建议大多合理。**`OnFilesDrop` 与 `OnHover` 已采纳**，本地补丁从 21 项减到
19 项；Markdown 行高可部分采纳；折叠动画和点定位面板需要单独评估，不建议为了“零补丁”
而牺牲现有交互。

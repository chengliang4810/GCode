# 审计后续五项修复（2026-11-16）

> 当前逐项状态统一见[审计总表](audit-closure-2026-11-16.md)。本页保留该轮历史事实，不再作为当前待修清单。

## 行为变更

| 问题 | 当前行为 | 回归覆盖 |
| --- | --- | --- |
| 附件传输与批次内存 | HTTP 上传采用二进制正文，删除 JSON/base64 上传；读取前检查整个批次，打开时复核剩余额度和大小。单文件 24 MiB、批次 96 MiB、数量 20 的限制不变。 | 真实客户端与宿主字节往返、来源会话、已知/未知长度、截断、空正文、超限提前拒绝、文件增长和批次预检。 |
| 删除会话后 UI 状态残留 | 接受权威快照后按会话集合回收专属草稿、目标编辑、侧聊、消息及轨迹状态；保留其他会话与新会话画布草稿。 | 删除选中/未选中会话、忽略旧快照、正文卸载、归档、重复清理。 |
| 超大 SSE 反复重试 | 单行及多行累计超过 8 MiB 的事件产生终止错误，分类为 `response_too_large`。 | 超限事件、错误包装、Gateway 只调用一次且不产生重试事件。 |
| Hook 搜索 Token 泄露 | 搜索 Token 纳入现有敏感值集合，同时处理原文及 URL/JSON 转义形式。 | 所有诊断字段、转义值、普通文本不变。 |
| 隐藏目录搜索 | `IncludeHidden=false` 按完整相对路径段过滤隐藏文件和目录。 | 根/嵌套隐藏目录、Windows 分隔符、普通点号与显式包含隐藏项。 |

全局混合用途展开状态未统一删除；进行中的附件导入计数由异步完成回调释放。
远程附件仍逐个导入，不提供整个批次的原子提交。核心保存附件仍有同步文件操作，
不能将本次改动描述为所有附件 I/O 均已移出状态锁。

## 验证

使用仅含已提交基线与本轮修改的独立源码导出，排除其他任务未提交的实现。
整仓 `go build ./...`、`go vet ./...`、`go tool mygo vet .` 通过。
桌面会话、快照、侧聊、目标、待发送消息及共享控件回归通过（36.342 秒）。
五项定向 race 检查通过；附件新增边界测试另行补跑 race。
Engine 全量通过（426.557 秒），Model、Remote、attachmentio、Contracts 全量通过；
附件新增边界定向 race 通过（15.542 秒）。原始日志归档到本机 `output/session-audit-five-fixes-20261116/`。

同为 24 MiB 上传、仅测 HTTP 边界且使用 fake importer 的三次单轮 benchmark：
25,185,752–25,193,632 B/op，约 24.02–24.03 MiB 累计分配。
修复前 JSON 探针为 159,407,440 B/op，累计分配约减少 84.2%。
该值不是峰值 RSS，不包含核心保存成本，也不证明所有附件场景的端到端性能。

未运行真实模型供应商、Windows 原生窗口、GitHub Actions 或掉电实验。
当前共享脏工作树包含其他任务的 Go 源码备份，整仓构建可能受混合 package 影响；
上述构建结论只对应独立导出版本。未安装或推送本轮修改。

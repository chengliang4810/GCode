# 发送消息的即时反馈

主对话、新建对话和侧聊在接受发送操作后，立即清空输入框并显示待确认的用户气泡，
不等待核心执行命令、持久化或模型响应。正文、附件和网页批注均保留在展示投影中。
新建对话的输入框仍使用原有停靠动画，用户气泡不跟随该动画延迟显现。

业务状态仍由核心拥有。本地待确认气泡不写入 `Snapshot.Messages` 或执行历史，
也不会向模型增加一条输入。核心返回正式消息或排队结果后，以 `RequestID` 对应并
移除本地投影；相同正文的两次发送具有不同标识，不通过文本匹配。
新建会话只收到摘要时，投影跟随会话保留，直到对应的正文订阅加载完成。
在运行中发送的消息确认入队后，使用现有队列行显示，不提前表示它已经开始执行。

发送失败时，气泡保留原始内容，并显示“发送失败”、错误详情悬停提示、重试和关闭操作。
重试提交原始请求，不覆盖发送后继续编辑的草稿或附件。输入框为空时，仍恢复原草稿，
便于直接编辑后重新发送。侧聊成功回执只结束待确认状态，不再清理后续编辑内容。
这些发送失败使用气泡内的恢复操作，不打开阻挡重试按钮的全局错误弹窗。

正式用户消息和队列项保留请求标识。核心对已入队或已成为用户消息的请求去重，
包括队列切换为下一轮、原队列运行标识改变之后的重试。
离开或删除会话不会将旧发送的失败内容写入其他会话；新建画布使用草稿代次隔离旧回执。

## 验证入口

- `internal/desktop/local_send_test.go`：持有后台发送任务，检查首个构建帧即有气泡；
  覆盖主对话、新建对话、侧聊、深浅主题、900/1320 宽度、附件、不同确认顺序、
  同文案的不同请求、队列确认、创建时正文尚未加载、失败重试及新草稿保护。
- `internal/engine/send_identity_test.go`：真实 Go 核心与私有模型端点，验证消息和队列
  的请求标识、排队期间重复请求、队列衔接后的重复请求。
- `internal/e2e/message_send_feedback_test.go`：原生窗口与真实本机核心，私有模型端点
  持有响应；检查等待模型期间只显示一个用户气泡、持久化请求标识、失败后的重试和
  新草稿保护，覆盖浅色新建对话及深色 900 宽度的已有对话。

组件测试中的持有任务证明核心接受前的展示行为；原生测试证明本机窗口与核心衔接。
私有模型端点不证明真实供应商的网络、认证或响应性能。

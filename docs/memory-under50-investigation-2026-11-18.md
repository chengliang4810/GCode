# 空闲内存收紧到 50 MiB 以下（2026-11-18）

## 结论与口径

目标口径为 macOS 物理内存足迹（vmmap Physical footprint），同时记录 RSS。
用户真实配置、原有全屏窗口、无运行任务时，此前物理内存足迹约 106 MiB。
本轮正式构建已安装并重启，稳定空闲采样约 47 MiB，下降约 56%。RSS 仍约 93 MiB。
不能据此声称 RSS 低于 50 MiB，也不保证执行任务、打开多张图片或 WebView 时仍低于 50 MiB。
没有关闭功能、修改用户设置、降低窗口分辨率或缩小附件原图。

## 实施内容

### 1. 安装包使用系统原生 Dock 图标

`setApplicationIcon` 原先在 macOS 启动时将 1024 px PNG 再次传入 `NSApplication.setApplicationIconImage:`。
实际 .app 已提供同源、多尺寸 ICNS。重复覆盖导致常驻约 32 MiB 的 CoreGraphics 图像缓存。
安装包现在使用 AppKit 从 ICNS 选择图标；直接运行开发可执行文件时继续设置品牌图标，Linux/Windows 行为不变。
已有素材回归证明 ICNS 的 1024 px 表示与 PNG 同源；原生普通窗口的前后截图逐像素一致。

独立资料目录原生对照（25 秒）：

| 场景 | 原图标路径 | 原生 ICNS 路径 |
| --- | --- | --- |
| 普通窗口 | 70.3 MiB | 37.7 MiB |
| 全屏窗口 | 71.0 MiB | 37.8 MiB |
| 全屏 + 复制用户外观设置 | 71.1 MiB | 38.1 MiB |

这些目录不含用户历史数据；真实配置结果另行采样，不直接将这些数字当作用户应用总占用。

### 2. 图片只预加载当前投影与待发送内容

真实配置堆采样中，约 21 MiB 累计来自 `App.prefetchMedia` 的资源读取和原图解码。
原 `snapshotMediaRefs` 遍历 `Snapshot.Attachments`，但它是全局存储索引，包含未打开的历史附件。
现在只收集当前已投影消息和排队消息中的图片。主输入框、侧聊导入以及草稿恢复显式预加载其附件。
保留后台解码、原始分辨率、点击预览、缩放、发送和附件文件本身；没有删除历史图片。

真实配置诊断进程（均已经取消重复 Dock 图标）：

- 收紧前物理内存足迹约 76.5 MiB。
- 收紧后约 52.4 MiB，原 `image.NewRGBA` 大头从存活堆采样中消失。

诊断构建临时包含一次性堆采样代码，只写本地文件；最终生产构建已移除。

### 3. 项目文件索引复用不可变字符串

目录扫描原本分别保留绝对路径派生的相对路径、文件名、完整 ID，以及每个条目的父目录 ID。
现在路径、名称和父 ID 都切片引用该文件 ID 的同一份不可变字符串，字段内容与文件枚举逻辑保持一致。
同一夹具（24 个目录、每目录 64 个文件）的分配次数由约 8268 次降至 6704 次，减少约 19%；分配字节从约 1.74 MB 降至约 1.61～1.64 MB。
这主要降低大项目索引的重复字符串和扫描分配，并非更改文件索引范围或忽略规则。

### 4. 自定义背景着色器按需编译

移除 App 构造时无条件编译背景着色器的调用。
在背景图实际加载完成的控制器提交阶段编译，仍在绘制前准备就绪；绘制回调不启动加载或编译工作。
隔离堆测量中，无背景时 App 创建后的 HeapAlloc 从约 7.70 MiB 降至 7.42 MiB。
自定义背景、调整、替换与最小窗口测试通过，着色器代码与效果没有变化。

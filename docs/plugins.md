# 插件管理

设置中的“插件”只显示已安装插件，空列表与已有插件时都提供“前往插件市场”入口。
“插件市场”是独立菜单，紧跟“模型设置”；页面右上角为“添加市场源”，其左侧图标打开
市场源管理弹窗，可编辑、刷新和移除来源。添加来源也在弹窗中完成。
市场目录支持文本搜索和来源 tab 筛选，第一个 tab 固定为“所有”，其后为各市场源；
移除当前选中的来源后自动回到“所有”。目录每页最多构建 30 个插件条目，使用共享按钮翻页，
避免数千条市场记录同时进入原生控件树。搜索和来源筛选仍覆盖完整目录，条件变化时回到第一页；
刷新后目录缩小时自动收回有效页码。

目录使用共享 `controlTileButton` 卡片，在共享页面框内按可用宽度自动换行，窄窗收为单列。
卡片显示名称、单行省略的描述和市场/版本摘要；点击整张卡片打开“插件详情”弹窗。
弹窗展示完整可选择的描述、市场、版本、作者、分类、主页、组件与校验提示；空信息不显示。
安装入口位于详情弹窗底部，已安装或正在操作的条目不可重复安装。关闭弹窗、切换设置页或
目录移除当前条目会清除详情选择；已打开的详情跟随宿主最新目录投影更新。

“添加插件市场”弹窗只填写一个地址：GitHub `owner/repository`、Git URL、
市场清单文件或目录。支持拖入单个文件/目录、选择目录和回车提交；
不要求填写市场名称、类型或 Git 引用。类型由宿主识别，名称取自市场清单，
添加成功时来源和已加载的目录一起保存，随后即可安装插件。
添加期间禁止重复提交，失败时保留输入并显示错误，不登记无效来源。
远程连接中的路径属于宿主，不能通过客户端目录选择器或拖放提交客户端本机路径。

页面完全使用原生 MyGo 共享控件，只提交 `contracts.Command`，目录获取、Git 操作、
依赖检查和文件写入均由实际业务宿主完成。页面不内置插件目录，不直接访问市场网络。
插件只有用户级安装，安装身份为 `插件名@市场名`，在宿主的所有项目中使用同一份启停和配置。
安装命令与持久化记录不再包含 scope 或 projectPath，也不保留项目级、本地级的安装与覆盖逻辑。

运行依赖安装在实际业务宿主上；连接远程服务时，在远程主机配置，客户端本机安装不能替代。
GitHub/Git 来源需要宿主 `PATH` 中有 `git`，凭据由该宿主的 Git 配置或凭据管理器提供。
`Glob` 与 `Grep` 在进程内自行遍历目录并匹配，不需要 `PATH` 中有 ripgrep（`rg`）。
`Bash` 工具在 Windows 使用 Git Bash，可通过 `RCODE_GIT_BASH_PATH` 指定 `bash.exe`；
不会把 Bash 脚本翻译成 PowerShell，也不会静默交给 Windows 的 WSL 启动器。
Linux/macOS 的 `Bash` 工具需要 `PATH` 中有 `bash`。
command Hook 的默认解释器另由 Hook 执行器决定：Windows 优先 Git Bash，缺少时当前会选
PowerShell；显式 `shell: "bash"` 不会回退，亦可用 `CLAUDE_CODE_GIT_BASH_PATH` 指定路径。
Linux/macOS 的默认 Hook 用 `sh`，显式 `shell: "bash"` 用 `bash`。
需要 Bash 语法的 Hook 应显式声明 Bash。显式 PowerShell Hook 目前只支持 Windows，
要求宿主有 `pwsh` 或 `powershell`。
宿主 MCP 连接在业务调用前探测当前协议：支持 2026-07-28 stateless discovery，
也支持服务拒绝探测或超时后进行握手版初始化。设置页连接诊断、普通运行、插件 MCP
及压缩 Hook 的模型执行复用同一连接入口；不会把 initialize 当作 2026 协议请求。
插件显式敏感字段也作为进程内私有元数据传给 MCP 红化器，不依赖环境变量名称猜测。
MCP 工具保留完整命名空间，超过 128 字符时只跳过该工具并记录诊断，同服务器其他工具继续可用。
模型协议边界另作过滤：Chat Completions 最长 64；Messages 与当前 Responses 路径允许到 128，
被排除的名称及限制会传给本轮 worker，不截断名称或生成别名。Responses 最新参考只在
namespace 内函数字段明列 128，flat 函数字段未另列上限；这里的 128 是产品边界，
不代表已经用用户账号验证所有供应商的同协议实现。

插件自己的脚本和 MCP 服务可能另外需要 Node.js/npm、Python/uv、应用程序、
外部账户、API 凭据或操作系统组件；GCode 不打包这些运行环境，安装插件也不会自动满足它们。

市场源支持 GitHub、Git、宿主目录、清单文件和清单 URL；可以维护引用及刷新目录。
默认来源由业务核心提供。来源错误、后台操作状态、插件组件与校验问题直接显示在页面。
“安装成功”仅代表宿主安装操作完成，不能替代真实模型、依赖、MCP 或 Hook 执行验收。

当前尚未执行的组件包括 LSP 服务、输出样式选择、channels 通知和 experimental 扩展；
这些定义会保留并在插件问题中显示。`.mcpb`/`.dxt` MCP 二进制包不会自动安装。
插件源的 npm/pip 包形式尚未实现，不能把“插件脚本调用 npm/pip”误当成“支持 npm/pip 插件源”。
未允许的插件 settings 字段和未识别的 manifest/Hook 字段会报告问题，
不按“加载了清单”宣称对应功能已运行。当前实现拒绝 `dangerouslyDisableSandbox`，
返回明确的不支持错误。

已安装页提供启停、更新、卸载及 manifest 声明的配置项。
公开快照只包含配置项定义和是否已配置，不包含已保存的值。
敏感项使用密码输入，离开编辑器或提交后清除页面草稿。
留空不修改已保存值；要清除一个值，应使用独立的删除配置操作。

配置保存会校验 `string`、`number`、`boolean`、`directory`、`file`，并应用
`options`、`min/max` 与 `multiple` 约束；不支持的类型、错误约束及不合法默认会明确报告。
原生字符串输入中，数值与布尔使用 JSON 标量，多值使用 JSON string[]；路径和普通字符串
保持原文，既不检查路径是否存在，也不再次展开值内的美元变量。复杂默认值使用 JSON，
不会转换成 Go 的列表或 map 显示格式。枚举仅支持非敏感、非多值的字符串项。
有效默认值也计入“已配置”，包括 false、0 与空数组；公开投影不含默认或保存的实际值，
只携带约束、是否存在有效默认、是否有保存覆盖等元数据。清除覆盖后会重新采用默认值。
显式清除仍可撤销 required 字段的已保存凭据，缺少默认时显示未配置；未知字段不能保存或删除。
敏感默认、敏感列表成员及其转义形式在技能、Hook、MCP 的输出边界统一红化；运行中的 Hook
冻结其敏感键定义，插件更新不会使旧规则丢失红化信息。插件私有值当前仍由宿主私有配置文件
保存，不宣称已经接入 macOS Keychain、Windows Credential Manager 等系统保险库。

只有实际保存过的字段显示“清除已保存值”；仅使用默认值的字段不会显示该操作。
界面不显示默认值或已保存值的内容。布尔值与枚举使用共享选择器，
数值标明范围，多值字符串明确使用 JSON string[] 格式输入；
选择“保持不变”或留空不会把默认值误写成用户配置。

市场登记、安装包和插件私有配置保存在固定配置目录，默认 `~/.gcode`。
插件运行时的 `${CLAUDE_PLUGIN_DATA}` 位于会话绑定数据根的
`plugins/data/<安装身份摘要>/`；受管会话环境文件位于该根的 `plugins/sessions/`。
技能动态脚本、Hook、MCP 配置展开及插件子 Agent 使用同一会话根；
插件安装路径 `${CLAUDE_PLUGIN_ROOT}` 保持在固定配置目录。
切换运行数据目录不复制插件数据，已有会话续跑仍使用原根，新会话使用新根。
不属于会话的运行资源操作使用当前活动根。历史根不可用时如实失败，
不在配置目录或当前根建立替代数据。插件持久数据不按缓存清理规则删除。

插件页与模型、技能、命令等设置共用页面外框和控件实现。
它不恢复已暂停的视觉对齐目标。组件测试和实现截图仅证明页面行为及布局约束，
不证明插件市场达到 90% 可运行率；该指标只按冻结的官方市场及真实逐插件执行证据统计。

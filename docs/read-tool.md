# Read 工具

当前公开工具名为 `Read`，接收 Claude 风格参数 `file_path`。文本与图片能力共用一个工具。本地桌面和无桌面宿主共用实现；
文件从实际执行宿主的会话工作目录解析，相对路径和绝对路径均可使用。
没有新增本机 HTTP/RPC，也不要求 WebView、Node、Python 或外部图像程序。

本次只参考 Pi 与 Claude Code 的功能行为，以本项目的 Go 接口独立实现，
没有复制、翻译或引入它们的源代码。图像处理复用现有标准库和已固定的 `golang.org/x/image`，
没有新增依赖或变更项目许可证。

## 输入与返回

```json
{"file_path":"screenshots/result.png"}
```

图片读取结果包含简短文字说明与类型化图片；Base64 不作为普通文本交给模型。
`model.ToolOutput` 统一承载 `Text`、`Images`、`Data`，所有现有内置工具与 MCP 工具使用同一返回接口。
`Data` 用于 Hook 的结构化 `tool_response`：文本结果为 `type=text` 与
`file.filePath/content/numLines/startLine/totalLines`；图片结果为 `type=image` 与
`file.base64/type/originalSize/dimensions`。模型图片仍使用独立的类型化附件。
图片进入 `model.Message.Images`，随执行历史保存、恢复和深克隆。
UI 工具活动只接收文字说明，不把图片 Base64 复制到工具输出和公开快照。
本轮没有增加 UI 图片预览。

三种适配器分别处理协议位置：

| 协议 | 工具图片的请求形式 |
| --- | --- |
| Chat Completions | 先发送同批全部 `tool` 文字结果，再追加携带图片的 `user` 消息；说明关联工具调用 ID |
| Responses | `function_call_output.output` 使用 `input_text`、`input_image` 内容数组 |
| Anthropic Messages | `tool_result.content` 使用 `text`、`image` 内容数组 |

普通文字工具结果仍以对应协议的字符串字段发送。工具执行失败时只保留错误文字，
不发送未完成的图片。目标模型必须支持图片输入；服务商拒绝会正常报告，不伪装成识图成功。
这不新增模型名称猜测或固定供应商目录。

## 图片处理

- 支持 PNG、JPEG、GIF、WebP、BMP；通过实际文件内容识别。BMP 转为 PNG。
- GIF 读取第一帧并保留逻辑画布、帧偏移及透明背景；不承诺理解完整动画。
- JPEG 识别 EXIF 1–8 方向并归一化，避免缩放后旋转、镜像信息丢失。
- 原始文件上限 24 MiB；解码前检查总像素不超过 3200 万、单边不超过 32768。
- 输出自动缩至单边最多 2048，保持比例，不放大原图。
- 输出 Base64 最多 4 MiB。优先保留符合限制的原图；需要重新编码时先尝试 PNG，
  超预算的不透明图尝试 JPEG 降质，透明图保持 PNG；必要时继续缩小尺寸。
- 返回说明包含原始和展示尺寸；缩放后提供坐标比例。JPEG 原始尺寸按归一化方向计算。
- 最多两个图片处理任务同时解码，限制并发内存；文件读取、解码、缩放和编码阶段之间
  检查取消。标准库单次解码/缩放/编码本身不能立即中断。
- 损坏、不支持、超限图片明确报错。SVG 作为文本读取，不在这里渲染；不新增 PDF 读取。

这些限制是 GCode 的本地处理预算，不代表所有服务商的当前 API 上限。
压缩和缩小可能影响细小文字与像素细节；文字说明会给出实际展示尺寸。

## 文本读取

```json
{"file_path":"main.go","offset":1,"limit":300}
```

`offset` 是从 1 开始的行号，默认 1；`limit` 默认 2000，范围 1–2000。
`offset` 和 `limit` 不用于图片，误用时返回明确错误。
文本必须为 UTF-8，文件上限 16 MiB；输出最多约 64000 字节，截断保持 UTF-8 完整。
分页输出会给出已知的下一行 `offset`；超长单行会明确报告该行被截断。
单行文本超过扫描器约 2 MiB 上限时明确报错。目录、非普通文件、PDF 和其他二进制内容
不会当作可读文本输出；尚未实现 Claude 的 PDF pages 或 notebook 专用读取能力。
旧 `read` 名称和 `path` 参数不再接受，没有兼容别名。

上下文容量估算现在考虑图片数量及像素的保守启发值，不把 Base64 长度当文本 token，
也不将估算声称为模型服务商的视觉 token 用量。历史前缀压缩后，摘要会保留图片存在的
文字提示及工具调用的原路径，必要时 Agent 可以再次读取；近期图片保持原始结构。
